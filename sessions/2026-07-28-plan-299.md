### What changed and why

1. **M1a — allowlist guard.** `BLOCKED_ENTITY_TYPES` blocklist replaced with an allowlist
   check against `ALL_USER_ENTITY_TYPES` (same import pattern as `admin.js:5`). Confirmed
   `signed-users-db`, `users`, `GEMINI_SHOTS`, `GEMINI_USAGE` are absent from the allowlist
   (all four were already absent — no removal needed).
2. **M1b — client-caller reconciliation (hard gate).** Grepped every literal storage key
   passed to `StorageService.query/put/post/replaceAll` in `src/app/core/services/*.ts`.
   All real backend keys are now in `ALL_USER_ENTITY_TYPES` except two that were missing
   and would have silently 403'd: `EQUIPMENT_CUSTOM_CATEGORIES` and `MENU_EVENT_TYPES` —
   added both. `cook_view_last_recipe_id` is `sessionStorage`-only (not routed through
   `StorageService`) — correctly excluded. `signed-users-db` stays excluded — it's already
   blocked today by the auth router boundary, not a caller this route should serve.
3. **M1c — atomic bulk replace.** `PUT /:type`: conflict-id query now runs before any
   delete (no more `Promise.all` race with `deleteMany`). `deleteMany` + `insertMany` run
   inside a `mongoose.connection.startSession()` transaction
   (`session.withTransaction`, `{ session }` on both calls, `insertMany` uses
   `{ ordered: true, session }`). On abort, responds `500 { error: 'Replace failed, no
   changes were made' }`. Fallback for standalone Mongo (local dev, no replica set —
   `startSession`/`withTransaction` reject with error code 20): insert new docs first
   flagged `_pendingReplace: true`, `deleteMany` the old (unflagged) docs, then
   `updateMany` to clear the flag. Documented in a comment above `replaceCollection`.
4. **M1d — tombstone fix.** `PUT /:type/:id` filter now includes
   `_userDeleted: { $ne: true }`, matching the `GET /:type/:id` filter — editing a
   soft-deleted (tombstoned) master-clone from a stale tab now 404s instead of silently
   resurrecting it.
5. **M1e** — POST handler and its master-propagation comment left untouched, as scoped.
