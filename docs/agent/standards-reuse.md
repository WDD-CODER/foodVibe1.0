# Reuse standard — read what exists before you build

Load this before creating a component, a shared util / pipe / service, a component-stylesheet class, an engine class or a
design token. What exists: `docs/brain/inventory.md` (generated by `node scripts/inventory.mjs`; never edit it). The families
and when to use each: `docs/brain/component-families.md`.

## The decision ladder

Find the family for the job in the registry first, then take the lowest rung that works:

1. **Use as is.** The shared piece already does the job.
2. **Use with existing inputs.** The same piece, configured through inputs or variants it already has.
3. **Extend the family.** Add an input, a variant or a hook to the shared base — never a page-local copy. Update the
   family's entry in the registry in the same branch.
4. **New family — only with a justification.** Nothing in the registry fits. Build it where shared code lives, never
   page-local, and add a `### <family-id> — <title>` entry to the registry in the same branch. The plan's row says why.

**Sibling rule.** When a shared piece would need more than about three variant flags to cover the new case, make a
sibling in the same family that shares the logic, not another flag.

**Prefer structure over reminders.** A behaviour or a style that every use needs belongs in the shared base, so a new
use gets it without remembering it. A reminder in a doc is the weakest fix.

## Plans — the `## Reuse Check` section

Every plan lists each new piece it creates, the family it searched and the rung:

```markdown
## Reuse Check
- Supplier picker in the order form — family: search-combobox — rung: 2 — why: its filter input covers it
- Cards layout for the list shell — family: list-page — rung: 3 — why: the menu library needs a grid
- Event timeline strip — family: none — rung: 4 — why: no shared piece shows a dated sequence
- none — this plan only changes server code
```

Rungs 1–3 name a registry family; rung 4 needs `why:`.

## Plans — an adopted package (the `## Adopt Check` section)

A rung-4 row or a new dependency gets an `## Adopt Check` row: is there a maintained package that already does it
(`docs/agent/adopt-check.md`, checked by `node scripts/scope-check.mjs --adopt --plan=<path>`). An `adopt` or `wrap`
verdict goes through one wrapper in the shared code: the plan adds a Reuse Check row for the wrapper (rung 4, a new
family) and its family entry in the registry. Pages and features import the wrapper, never the package, so replacing
the package later changes one place.

## Plans — the `## Defaults` section

A behaviour the project decided once lives in `_shared/product-defaults.md`, never in each plan. Every `on` default a plan
triggers gets one row: `- <id> — applies — how: <piece>` or `- <id> — exception — why: <one line>`. When a default's `how` is
"call X in every feature", move it into the shared base (the form base owns the leave question, the single write path owns
the log entry): structure over reminders. `node scripts/scope-check.mjs --defaults --plan=<path>` fails a plan without the
row. The inventory's `## Defaults (on)` block lists each `on` default with its rule and piece.

## What enforces it

| Check | What it stops |
| --- | --- |
| `node scripts/scope-check.mjs --reuse --plan=<path>` | a plan with no section, an empty one, an incomplete row |
| `node scripts/kit-checks.mjs --plan <path>` (`reuse-new-items`) | a new component, shared util, component-stylesheet class, engine class or token that no row names; the message names the nearest family or existing class. A rung 3–4 row with no change to the registry file fails too |
| `node scripts/reuse-lint.mjs --diff=<base>` and the ratchet (`reuse-copies`) | a new copy of a registered family: rules in `scripts/lib/registry-families.mjs`, counted per family as `reuse-copy.<family>` — an old copy never blocks, a new one does |
| `node scripts/reuse-lint.mjs --check-registry` | a registry path that is gone, a rule whose family has no heading |

The kinds checked come from the `reuse.*` settings (`componentFiles`, `logicFiles`, `componentStylesheets`,
`sharedDirs`, `globalStylesheet`, `enginePrefix`); an empty setting means that kind is not checked. Without `--plan` (CI)
`reuse-new-items` is skipped with a note; the ratchet still runs.

A row names a piece by its file stem (`badge` for `badge.component.ts`) or its selector (`.badge-title`).

## What the style checks stop

`node scripts/kit-checks.mjs` reads the added lines of the files in `reuse.componentStylesheets`. Nothing runs when that
list is empty. A token kind is checked only when its `styleqa.tokenPrefixes` key is set and `styleqa.tokenFiles` holds at
least one definition with that prefix. A token definition line, a `tokenFiles` file, `0`, `100%` and `auto` are never reported.

| Finding | What it stops | The fix |
| --- | --- | --- |
| `style-raw-color` | a `#hex`, `rgb()`, `rgba()`, `hsl()` or `hsla()` value | use a `--color-*` token (the prefix the project set) |
| `style-raw-font-size` | a px, rem, em or pt `font-size` | use a font-size token |
| `style-raw-radius` | a px, rem or em `border-radius` | use a radius token |
| `style-raw-shadow` | a px, rem or em length in `box-shadow` or `text-shadow` | use a shadow token |
| `style-raw-blur` | a `blur(<length>)` in `filter` or `backdrop-filter` | use a blur token |
| `style-raw-spacing` | a px, rem or em length in `margin`, `padding` or `gap` | use a spacing token |
| `style-duplicate-block` | an added block of 2+ declarations that has the same properties and values as a block in another component stylesheet or as an engine class; the message names `<file>:<line>` | reuse that class, or move the block to the engine stylesheet |

The ratchet counts the same debt over the whole tree, so old debt never blocks and new debt does: `style-raw.<kind>`
(for example `style-raw.color`), `style-duplicate-block`, and `style-duplicate-class` (a class name defined in more than
one component stylesheet). Fix a class name by sharing the class, then run `node scripts/debt-baseline.mjs --lower`.

## The first install into an existing project

When a project has no registry file, the first install (or sync) runs `node scripts/reuse-scan.mjs --write` once. It writes
the registry as a draft — one `### <id> — <title>` per shared component found under `reuse.sharedDirs`, the first line
`DRAFT — written by the kit's scan on <date>; review every family, then delete this line` — and a first debt baseline from
the project's current counts, so old debt is counted, never blocking. Review the draft: fill each `when:`, merge or delete
families, then delete the DRAFT line. The baseline only goes down: after a branch removes debt, run
`node scripts/debt-baseline.mjs --lower`. A project that already has a registry is left byte-identical.

**Angular examples.** A new piece is a `*.component.ts`, a pipe or a service, a class in a component `.scss`, a `.c-*`
engine class or a token in `src/styles.scss`. Shared code lives in `src/app/shared/` (UI) and `src/app/core/` (logic),
never in a page folder. Import it through the path aliases, not `../../core/...`. A shared component is styled through its
own inputs or variants, never from a page stylesheet or with `::ng-deep`.
