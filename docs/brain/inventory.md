# Inventory

Generated by node scripts/inventory.mjs — do not edit

## Families
- `acting-banner` · a persistent notice with an action must stay on every screen; a toast disappears and `app-front-desk-status-banner` has no action.
- `ai-cap` · a server path calls the model and must refuse once the business has used its monthly cap.
- `ai-draft` · an AI flow must store what the model suggested next to what the person saved, with a closeness score.
- `ai-learning` · code copies something into a `'__master__'` pool or lists a business's AI material for the platform admin.
- `ai-voice` · a screen or route sends a voice note to be turned into a transcript.
- `business-delete` · a business is deleted and everything it owns on the server must go.
- `chip` · a small rounded label, toggle, tab or filter. Do not add a page-local chip: pick a variant. The old `c-toggle-chip`, `c-tap-chip`, `c-tab-pill`, `c-filter-chip` classes no longer exist.
- `client-picker` · any screen that links a record to a client (new-inquiry dialog, event stage bar, the client section).
- `cloudinary-requests` · building a signed upload, expiring download link or delete request.
- `cost-badge` · a cost is shown that may be missing prices.
- `diag-invoice-queue` · several invoice files are approved one after another; never read or apply several at once.
- `diag-margin-report` · the diagnosis needs the menu margin per dish from recorded prices; never write a second margin calculation.
- `diag-menu-draft` · the diagnosis menu-reading route validates a request or a model reply and scores the draft closeness.
- `diag-volatility` · the diagnosis scores how much a product's price moved over time.
- `diagnosis-card` · the dashboard shows the consultant's diagnoses.
- `edit-gate` · a page offers save/edit on a business item.
- `empty-state` · an empty list or a search with no results.
- `engine-classes` · a style used by more than one component (buttons, inputs, modals, chips, empty state).
- `entity-data-service` · a new entity type needs a client data service.
- `entity-form` · a form edits a named entity, or must warn before leaving with unsaved changes.
- `entity-schemas` · a new stored collection needs a shape.
- `event-plan` · anything that computes quantities, costs or prices for an event.
- `feedback` · any wait, success or error the user must see.
- `file-store` · a server path stores, reads, links or deletes a private uploaded file.
- `form-field` · any form input with a label.
- `helpers` · any pure helper (time, number, text). Never page-local.
- `http` · any call to the server API; never a raw `fetch` or a hand-built `/api/v1` URL.
- `import-preview-embedded` · a second screen hosts the import preview; never copy the preview.
- `invoice-memory` · an invoice apply remembers printed names, a read looks them up, or a business is deleted and its memory must go.
- `invoice-read` · the invoice read route (`POST /api/v1/ai/invoices/read`) turns a photo or PDF into a header, a supplier suggestion and rows.
- `invoice-screen` · any browser screen that shows a price change, sends an invoice with the import save, or lists saved invoices.
- `invoice-trail` · the invoice apply route stores the invoice record, the price history rows and the draft closeness score.
- `kitchen-state` · state that several pages read or change (the loaded entity collections); never a page-local copy.
- `learned-data-erase` · learned data of a business must be removed; going private never erases (it only stops learning).
- `learning` · the platform admin explicitly erases what was learned (`POST /admin/businesses/:id/erase-learned`, `DELETE /admin/users/:userId?eraseLearned=true`); nothing else erases learned data.
- `learning-stats` · the platform admin needs accuracy numbers per flow over time (`GET /stats` in `server/routes/admin-learning.js`).
- `list-logic` · a list needs search, sort, filters or "clear all".
- `list-page` · any screen that lists entities.
- `loading-list` · any screen or test that needs "what goes on the truck" for an event.
- `logistics-extract` · a route turns an event's free-text notes into a draft logistics checklist.
- `modal-controller` · code needs to open a popup and await the result.
- `modal-shell` · any popup. Render the shell inside the owner's `@if (isOpen)`; never draw `.c-modal-overlay` by hand.
- `model-media` · a model call carries audio or a PDF.
- `module-gate` · a link, chip, screen, button or request belongs to a module. The server is the gate; the browser only hides.
- `modules-registry` · the server gate or the browser service asks whether a business has a module. One shared file, so both use the same rule.
- `multi-pick` · the value is a list (allergens, labels, categories) and the user adds/removes chips.
- `number-box` · a box whose only content is an editable number. Not for rows that mix free text and numbers.
- `page-entry-loading` · a route needs its collection loaded first, or a screen opens only for the consultant's own module.
- `platform-erase-box` · page-local layout of the erase action; no shared family fits.
- `platform-history` · any platform change line of the business history; never format `{ field, from, to }` elsewhere.
- `price-impact-panel` · a screen must show what a price change does to recipe cost, computed by `RecipeCostService` before and after.
- `price-rises-card` · the dashboard shows recent price rises.
- `repair-script` · product sources already point at a foreign, unknown or empty supplier; the Human runs it (dry run first), never a build step.
- `search-combobox` · the user types to find an item (or a new one) and picks it — recipe/product/ingredient search, dish and category pickers, equipment search. Server searches pass `[clientFilter]="false"`; rich rows use an `<ng-template>` child.
- `server-auth` · a server route checks who is calling, scopes data to a business, checks a write permission or limits a rate.
- `stepper` · any +/− button that changes a number. The page keeps its own skin (cook-view ink set, menu paper pill).
- `stock-ai-draft` · a stock suggestion from voice or text is read and reviewed; never a second review UI for stock.
- `stock-extract` · a stock count text is turned into lines or a stock draft is scored; the model only returns spoken words, a number and a unit, never ids or sums.
- `supplier-picker` · a line may be bought from one of several priced suppliers and the owner chooses.
- `supplier-refs` · any code that copies or maps a product's `sources[].supplierId` between master and a business; never keep a master or foreign id.
- `taxonomy` · a page reads or adds a category, unit, label or kind.
- `unit-rates` · server code converts an amount into a product's base unit (a stock count); never write a second conversion.
- `user-alerts` · a person must be told something at once (a price moved beyond the threshold); a new alert kind adds a `kind` to the schema and a writer next to `createPriceChangeAlerts`, never a second list or bell.
- `voice-note` · a screen takes a spoken or typed note and needs it as text.

## Defaults (on)
- hints-in-tooltips — An explanation of a control in a dialog shows as a hover tooltip on that control (a title plus an accessible description), not as text on the modal. — native [attr.title] plus [attr.aria-label] or aria-describedby on the control, as the history button of platform-business-dialog does (plan 638); no new tooltip piece
- unit-dropdown-add — Every unit-of-measure dropdown offers an 'add unit' option that opens the add-unit popup, so a missing unit is created on the spot. — app-custom-select with the add-option row (docs/agent/standards-domain.md Add-option rule) calling UnitRegistryService.openUnitCreator (src/app/core/services/unit-registry.service.ts), as the product form does
- stock-count-unit-never-guessed — A counted line carries the unit the cook said or one the person picked, never the base unit by default; a row with no unit waits uncounted with the product units as chips plus the add-unit option. — spoken-unit.ts (unitForSpoken, unitChoicesFor) and stock-count.component (RowState.choose); the server reads the unit word from the text (server/utils/stock-extract.js unitWordFromText)
- leave-and-return — When a page sends the user to another page to act (e.g. add a product from the count), the current work is saved without asking, the other page opens prefilled with what the user already typed, and save or back returns the user to where they were with their work restored. — a return-to-origin helper (to be added in src/app/core/services/, family page-entry-loading: returnUrl in the query string plus the page's own draft saved before leaving); the auth guard's returnUrl (src/app/core/guards/auth.guard.ts) is the existing pattern
- app-list-container — Every list on a page uses the app's shared list container (app-list-shell with app-page-header), and each row is one c-list-row on a single line at every screen size. — app-list-shell (src/app/shared/list-shell/) with app-page-header (src/app/shared/page-header/), family list-page in docs/brain/component-families.md
