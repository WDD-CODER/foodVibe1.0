## Decisions
- Component selectors use the `app-` prefix (`app-event-stage-bar`, `app-event-notes-log`, `app-not-closed-dialog`, `app-new-inquiry-dialog`) · run-mode requires it; the plan text names them without the prefix.
- The "הזמנות" to «הזמנות לספקים» offer is skipped for now · plan 435 is not merged (spec: "only if 04.2 merged"). The stage bar has the `supplierOrdersAvailable` input (default false) and the `openSupplierOrders` output with the prompt (`open_supplier_orders_prompt`, «כן») already built, so plan 435's wiring is `[supplierOrdersAvailable]="true" (openSupplierOrders)="<its pill-row expression>"` in the page template, no `.ts` growth. The P0 line stays `[ ]` in the plan.
- The new-inquiry form is hosted in the library list component, opened by `?new=inquiry` · `menu-library.page.html` is not in the plan scope; the FAB action (page `.ts`), the header button and the URL all set the same param, so there is one open path and the form survives a reload. The saved/cancel events remove the param.
- The header «פנייה חדשה» button (P1) is hidden on phones (max-width 768px) · the FAB carries it there and the shared page header has no room for two buttons.
- Stage filter value `active` is the default and is not written to the URL; `all` and each stage key are (`?stage=`) · keeps the common URL clean. An unknown `?stage=` value falls back to `active`.
- The event-type picker in the inquiry form is pick-only (no add row) · event types are managed in the metadata manager; the add-option rule applies only to pickers that add.
- The inquiry also stores `eventTypeSnapshot` (via `EventTypeSnapshotService`, same as the AI create flow) when an event type is picked, and `servingType: ''` as the plan says · so the coefficient is frozen from the start (plan 441).
- `clientName` of a new inquiry is the typed name · the single field is labelled "שם הלקוח / האירוע" and serves both.
- A stage move with no event date is refused on the client first (no request) with `stage_needs_date`; the server's `DATE_REQUIRED` maps to the same text · saves a round trip, same result.
- Unknown error codes show `stage_change_failed` on a stage move and the existing `server_error` on a note call · `stage_change_failed` ("שינוי השלב נכשל") would be misleading for notes.
- A 403 shows no second toast from these components · the auth interceptor already shows `no_permission`.
- `src/app/core/breadcrumbs.md` and `src/app/core/services/breadcrumbs.md` added to the plan's scope block · the breadcrumbs check flagged the new service and util; two doc lines, small and required by the repo rule.
- Dialogs close on Escape through the component `host` metadata (`document:keydown.escape`), not `@HostListener` · run-mode: no `@HostListener` in new code.
- Stage bar client fields save on `change` through `MenuEventDataService.updateMenuEvent({ ...event, <field> })` · the generic PUT is a `$set` merge and strips the server-owned fields, so the whole event can be sent safely. Clearing both deposit fields stores `deposit: {}` (a PUT cannot unset a key).
- Desktop layout: `.menu-editor-shell.has-notes` becomes a two-column grid from 1024px (paper 720px, notes 20rem, sticky); below 1024px the notes log sits under the paper, as the plan says.
- Icon `message-square` registered in `app.config.ts` (`MessageSquare`); initial bundle 559.33 kB, under the 560 kB budget.
