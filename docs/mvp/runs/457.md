## Decisions
- One commit for S3-S6 + S12 instead of one per sub-task · the old rules can only be deleted once every call-site moved, and the four families share files (metadata-manager html carries tab, tap and toggle chips); S2 is its own commit.
- Added the four out-of-scope call-site files (`settings.page.html`, `prep-sheets.component.html`, `business-performance.component.html`, `not-closed-dialog.component.html`) to the work · the Goals grep needs zero uses to delete the old rules; the change is a class rename only (narrow exception, run-mode). Plan scope block updated.
- `.c-chip-group` gets `padding-block: 1rem` only when it directly holds a `--toggle` chip (`:has(> .c-chip--toggle)`) · the old `.c-toggle-chip-group` had it, `.c-tap-chip-group` did not; keeps both looks identical with one wrapper.
- Variants repeat all their values and sit after the old base `.c-chip` rule · base `.c-chip` (static label, many `c-chip teal/amber` uses) stays exactly as is, so those pills do not change.
- Literal colours replaced by tokens (pixel/colour difference, tiny): filter-chip border and hover `rgba(20,184,166,0.2)` -> `color-mix(in srgb, var(--color-primary) 20%, transparent)`; amber tone border `rgba(245,158,11,0.25)` -> `color-mix(in srgb, var(--color-warning) 25%, transparent)` (`--color-warning` is #d97706, was #f59e0b-based); red/teal tone borders likewise via `color-mix`. Only the new `--*` tone/`--filter` variants use these; legacy `.teal/.amber/.red` rules untouched.
- `.c-chip--home` is the combined selector `.c-chip--tab.c-chip--home` and the markup binding is `[class.c-chip--home]` · the home chip is only ever used with `--tab`.
- Phone checkbox exclusion in `styles.scss` (`:not(.c-toggle-chip > input)`) renamed to `:not(.c-chip--toggle > input)` and the `.c-filter-section > .c-toggle-chip-group` flex rule to `.c-chip-group` · these existing lines had to follow the rename or phone toggle inputs / filter wrapping would break.
- Spec files changed only for class names (tab-chips: `a.c-chip--tab`, `.c-chip--home`; metadata-manager: `.c-chip--tab`, `button.c-chip--tap`, `.c-chip--toggle input`).
- `--removable` + `__remove` added to the engine (P0) but no call-site uses it yet · the only removable chips (`custom-multi-select-chip`, `scaling-chip`, `ai-product-chip`) have their own radius/size/dynamic colour, so moving them is a visible change.
- S7-S11 deferred · every remaining class carries its own radius (xs/sm/md vs full), font size (0.6875-0.8125rem), border and often dynamic colour from data (`custom-multi-select-chip--colored`, `label-chip` background, `cv-chip-bg`). Moving them onto the engine either changes how the screens look (the plan forbids it) or needs a size/shape modifier per class, which would rebuild the 80-way drift inside the engine. A second pass should first agree 2-3 engine sizes/radii with the Human (design decision), then convert S7-S11. Frozen pages (recipe-builder, menu-intelligence, cook-view) were left untouched, so their net-line rule holds.
- S1 inventory lives in this file, not in `docs/session-state-<branch>.md` · run mode keeps the per-plan notes in the run file.
- Registered the chip family in `docs/brain/component-families.md` (P1).
