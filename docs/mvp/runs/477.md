## Decisions
- ADR file is `docs/brain/decisions/0026-staff-see-events-only-in-the-stages-the-owner-chose.md`, not `0024-...` · `0024` and `0025` were taken by plans 450/452 after the plan was written; added the `0026` path to the plan's scope block.
- Legacy events match by `{ stage: null }` (missing or null) instead of `{ stage: { $exists: false } }` · it is exactly the in-memory rule `event.stage ?? 'inquiry'`, so the two forms cannot disagree on a stored null.
- An empty list (`stages: []`) is accepted · the schema allows it; staff then see only events they created. Card lets the owner untick every chip.
- Saved list is de-duplicated and put in `EVENT_STAGES` order on the server (the client already sends it in order) · one stored shape whatever the body order.
- Stage chips built on plan 457's `c-chip c-chip--toggle` in `c-chip-group` (plan named the removed `.c-toggle-chip`) · reuse-first; no new `.c-*`.
- `computed` in the card is named `checked` (no `_`), not `checked_` as in the plan · `angularComponentStructure`: `computed()` never carries the `_` suffix.
- Card styles copy the coefficients card shell in its own `@layer components.staff-stages-manager` · no shared card component exists; the plan says "copies the coefficients card shell".
- The menu editor's 404 handling covers every 404 (hidden stage, deleted, other business) with `event_not_available` · all mean "this event is not available to you"; other errors keep today's path (rethrown).
- `stats.js` reads the business a second time through `withEventVisibility` (it already has `business`) · keeps one rule entry point; one indexed `findOne` per staff stats call.
- `menu-intelligence.page.ts` is growth-frozen, so the 404 path is a compact `.catch` in `loadEvent` and the page pays for it by folding the copy-pasted create/update block of `save()` and `saveAndWait()` into one private `persist_()` · net line count `27 added / 32 removed` (-5) vs origin/mvp-review; the menu-event service is outside this plan's scope, and the dedup keeps both save paths byte-for-byte equivalent (name fallback, prepareForSave, add/update, markSaved).
- `PUT /:type/:id` for staff on a hidden event now answers 404 instead of 403 (hidden events are "not found") · plan Technical Considerations; staff never created those events, so C-PERM outcome (no write) is unchanged.
