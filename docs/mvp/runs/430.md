## Decisions
- Data-type exclusions in `usage.js` are built from `SYSTEM_TYPES` (already exported by `server/utils/permissions.js`, no edit there), so `DICTIONARY_OVERRIDES` writes are not kitchen writes and the lists cannot drift.
- The read throttle is set before the write starts, so parallel GETs on app start cause one upsert.
- Bookkeeping calls (`/api/v1/log`, `/ai`, `/admin`, `VERSION_HISTORY`, `activity_log`) never count as writes besides `/auth/*` · the plan's Planner decision: C-USAGE counts writes on business data only. Exported as `NOT_BUSINESS_WRITE_PREFIXES`; the prefix match is exact-or-followed-by `/` or `?`.
- The recorder is a `res.once('finish')` listener, so the response is never delayed and a failing write is only a `usage.record.failed` warning · plan design.
- The read throttle is also set after a counted write · the next GET within a minute adds nothing, so a save followed by a refresh is one update.
- The "token without businessId, still 200" case can only be tested as: a token with a user but no business is rejected 401 by `attachUser` (plan 425 rule, unchanged), and a token with neither user nor business records nothing · the 200 variant cannot exist after plan 425.
- `weekBounds` accepts a `YYYY-MM-DD` string or epoch ms (ms is converted with `jerusalemDate`, the Israel date) · plans 447/448 will pass Israel dates.
- `business-team.test.js` waits 300 ms then replaces the usage records before the GET /team assertion · the earlier requests of that test are recorded after their responses and would race the expectation.
- Contract extension appended to `docs/mvp/mvp-map.md` (see below) · plans 447/448 import these exports.
- `server/routes/business.js` also imports `mongoose` and `usage-stats` · needed by item U5, inside scope.
