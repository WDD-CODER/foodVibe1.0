## Decisions
- Rehearsal DB = a fresh mongod on port 27099 seeded with a small pre-0006 data set · the machine's MongoDB service is stopped and `Start-Service` is denied; plan 424's seeded `foodvibe` copy is not available; the migration only needs the shape, not the volume.
- `server/migrations/0003-taxonomy-terms.js` added to scope (validates with placeholder `businessId` / `createdBy`) · the schema now requires both, and 0003 runs before 0006 stamps them, so its own validation (and its tests) would reject every term on a pre-0006 database.
- `src/app/core/services/taxonomy-store.service.ts` added to scope (`TermExtras` omits `businessId` / `createdBy`) · the required fields in `baseDocShape` broke `ng build` for every `taxonomy.add(...)` call; one type line, no behaviour change, no UI change.
- `requireAdmin` alias deleted and the `role` fallback removed from `requirePlatformAdmin`, `signAccess` and `toPublicUser` · plan B3; `isPlatformAdmin` is `user.isPlatformAdmin === true` only. The token still carries `role` until plan 426.
- `tombstoneSchema` keeps `createdBy` optional · a purged stub does not carry it (plan 424 decision, unchanged).
- `toStub` keeps `userId` only when the doc had one · `userId` is optional in the schema now.
- Taxonomy `referencedBy` rows (term-in-use 409) carry `businessId` instead of `userId` · the client only reads `name`; the owner field is a business now.
- `DELETE /api/v1/admin/users/:userId` answers 404 for an unknown user (was a silent `ok`) and, for a user who never got a business, still deletes their docs by `userId` · so a stray pre-migration account can still be cleaned up from the admin list.
- Owner delete is decided by `businessRole !== 'staff'` (a user with a business and no role is treated as owner) · deleting a staff user must never remove the business; the unknown case errs on the whole-business side only when a business exists and the role is missing, which migration 0006 never produces.
- The refresh sync gate reads `businesses.lastSyncedMasterVersion`; the sync stamps new clones with the business owner (`business.ownerId`) as `createdBy` / `userId`, whichever member triggered it · plan B7 ("Rule 1 clones stamped with the business owner").
- `reset-user-from-master.js` also keeps `--all-non-master` and `--orphans`, now by `businessId` · same script, same switches; `--business=<id>` added.
- The one remaining `it.todo` in `invariants.test.js` ("staff change only what they created and never money fields") stays, renamed to plan 427 only · it is the owner/staff permission rule (Out of Scope here), not tenancy.
- Old `userId` indexes are kept next to the new `businessId` ones · plan B8 (migration 0003's `--verify` checks `kind_key_user_unique`).
- Comment block above `push-to-master` in `generic.js` still describes the old "open to any signed-in user" tradeoff · the route is now `requirePlatformAdmin`-gated; left as history, not worth a rewrite inside this plan.
