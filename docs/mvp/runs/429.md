## Decisions
- `BusinessService` calls use `environment.apiUrl` (the base it and `TeamService` already use), not `authApiUrl` as the plan text says · one base for one router.
- The save toast and the `settings_invalid` toast live in the tab component, `BusinessService.updateSettings` just throws on a refusal · keeps the initial-bundle service small (budget margin is 0.18 kB).
- A 403 on save shows no second toast · the interceptor already shows `no_permission`.
- `server/test/business-route.test.js` and `src/testing/test-lucide-icons.ts` added to the plan scope · the existing GET test asserted the doc "as stored" (now has defaults filled); the shared test icon list needs `Building2` for the new tab icon.
- Save is enabled only when the form is valid and differs from the stored numbers · matches «שמור» disabled for invalid or unchanged in the plan.
- Number inputs are `type="number"` with `inputmode="decimal"`, `step="0.1"`, `dir="ltr"` · numeric keyboard on mobile, one-decimal entry.
- `GET /api/v1/business` returns the defaults-filled `settings` to staff too (contract: any member reads) · only the tab is owner-only; the server write stays owner-only.

- Fix round 2: the route write moved into `setBusinessSettings` in `server/services/business.js` (scope extended by that one file) · keeps the service as the only runtime writer of `businesses`; a missing business returns 404.
