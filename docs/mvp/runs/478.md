## Decisions
- Step 0 mapping against `origin/mvp-review-fixes`: `readAndFill_`, `matchWithAi_`, `view_`, `matchOf_`, `isMatching_`, `statusKey`, `ImportRowStatus` all ok, same names and shape as the plan describes (no refactor 450–458 renamed them). Row chip already ships the plan-457 modifiers `c-chip--teal` / `c-chip--amber` in `src/styles.scss` · switched the template from the legacy `.teal` / `.amber` classes.
- Status `matching` is derived in `view_` from a new `pendingIds_` signal (row ids sent to the AI step), set right after the exact matcher, cleared in `finally` · the instant preview is kept (`rows_.set` still runs before the AI call), only the status waits.
- Editing a pending row's name drops it from `pendingIds_` · the AI answer for the old text is ignored anyway, so the row falls back to name-only matching at once.
- The "unknown pack word" flag is hidden while a row is `matching` · it only applies to new rows and would otherwise flash.
- No spinner icon on the neutral chip, text «בודק…» only (key `import_status_matching`) · the `loader` Lucide icon is not registered in `app.config.ts` / test icons, and adding it is outside the scope block; the plan says "spinner or icon" as optional styling.
- While `matching`, the unit cell shows the parsed unit as read-only text and the purchase-unit / category cells show "–" · the row does not change shape twice. Rows that end up `new` become editable once, when the AI answers; rows that match keep the read-only existing-product cells they always had.
