## Decisions
- Add option sits last in the station list (`__add_station__` / `add_new_station`), "כללי" first · the select renders the add option itself and the plan says "one add option".
- Cancelling the add window restores the previously selected station · the select sets the sentinel value before the modal closes, so the header puts the old value back.
- `buildRecipeFromForm` checks the key with `StationRegistryService.hasStation` (the registry owns the lookup) · same pattern as the course check, and the spec fakes one service.
- After a station rename the manager reloads recipes and dishes (`reloadFromStorage`) · the server re-keys `defaultStation`, the cached lists must follow or the header would show "כללי".
- In-use removal relies on the server 409 and `TaxonomyStore.errorMessage` (names the recipes) instead of a client count · INV-3, the client never counts usage.
- Duplicate name in the manager shows `metadata_station_exists` before any write; duplicate in the header add window reuses the existing key (no second term) · registry rule from the plan.
- Unexpected errors: `logging.error` plus the existing `server_error` toast · no new dictionary key needed.
- No `.scss` edit: the new select sits next to the course select and flows in the existing header grid · the phone layout is covered by human card ③.
- Added `metadata-manager.page.component.spec.ts` to the plan's scope block (its jump-nav assertions count the sections) · small, required by the new section.
- `ensureDefaultStations` is called after `seedMasterTaxonomy` on both `seedMasterData` paths and returns its inserted count into the total · plan T2.
