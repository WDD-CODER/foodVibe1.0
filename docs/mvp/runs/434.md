## Decisions
- Table cells stay numeric in preview and Excel (`roundMoney`), `formatMoney` is not used · preview rows must equal the Excel rows exactly, and a ₪ string cannot be a number cell.
- Groups order: normal categories (Hebrew sort), then `line_status_unlinked`, then `line_status_deleted`; rows by name inside a group · the plan names the groups but not their order.
- A `no_conversion` row stays in its product's category group and carries the note in the note column · the plan only asks for the note.
- Total row: label `shopping_total` in the product column, amount in the line-total column, `partial_total` in the note column when `plan.partial` · keeps the 7-column grid.
- Engine errors go to preview `summary` (label = text, empty value) and to Excel rows after the total (bold total row) · per plan.
- All view reads `plan.dishCosts` by `${section._id}|${itemIndex}` and the item's own `derivedPortions`; cost per portion = cost / portions when portions >= 1 (unchanged rule) · plan W3 / P1.
- `MenuIntelligenceService` now injects `EventPlanService` instead of `KitchenStateService` + `RecipeCostService` (the private recipe lookup is gone) · plan W4.
- The page injects `EventPlanService` directly for `eventCost_`, `getAutoFoodCost` and `selectRecipe`; engine imports use relative paths because there is no `@engine` alias and `tsconfig.json` is outside scope · logged.
- Preview title stays the English "Shopping list" suffix and the Excel sheet name stays "Shopping list" · unchanged behaviour outside the plan.
- Excel unit-price column is dropped (the plan's column list has none) and line total is a value, not a formula · per W2.
- `ExportService` facade signatures unchanged; `recipes` is now `_recipes` in the two shopping-list methods · API stability.
- Dictionary file kept its CRLF line endings; keys appended at the end of `general` · hotspot is append-only.
