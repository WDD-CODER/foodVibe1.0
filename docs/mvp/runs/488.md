## Checker rounds
### Fix round 1
- [major] `arrivalOnly()` copied `arrived` / `hasInvoice` / `photos` from the stale staff copy for every shared row,
  wiping ticks and photos the owner added on other rows since the dialog loaded. **Fixed** in
  `server/utils/closing-rules.js`: the arrival-only path now only **adds** — a row's tick is
  `stored === true || incoming === true`, photos are the stored ones plus incoming ones not stored yet (capped at the
  schema's 10). Nothing stored is cleared on this path. Chosen over a client `changedKey` because that needs
  `event-pipeline.service.ts` (outside scope) and still could not tell an untick from someone else's tick on a stale
  copy. Trade-off: a staff untick / photo removal sent on a stale copy is not applied; the route returns the stored
  closing, the dialog refreshes from it, and the next untick goes through the normal (fresh-copy) path.
- New server tests (`events-closing.test.js`): the reviewer's scenario — stored s2 `actualPaid: 1100`,
  `hasInvoice: true`, `photos: [PHOTO]`; stale staff copy ticks s1 → 200, s1 `arrived: true`, s2 keeps
  `hasInvoice: true` and `[PHOTO]`; and a stale staff photo on s1 is stored next to the owner's photo
  (`[PHOTO, OTHER]`).

  s2 → `{"arrived":false,"hasInvoice":true,"photos":["https://x/p.jpg"],"actualPaid":1100}` (kept).
