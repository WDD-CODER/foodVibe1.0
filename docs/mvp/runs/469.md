## Decisions
1. **Plan 431 redirect tests replaced, not deleted** · the two specs "owner without a baseline is sent to the baseline screen once…" and "redirects when the business arrives after the card was created" now assert `navigate` is never called and the status is requested once (`setup-checklist-card.component.spec.ts`).
2. **H3-1 cause (read from code and specs, not seen in a browser)** · "no count shown" was the real cause: step 1 was a yes/no tick at 10 products, so one product could not change the card. A reload on revisit already happened (the card is created again when the overview opens). A failing-spec-first run was not done in a browser; the new spec "one priced product moves the card to «1 מתוך 5»" pins the behaviour. "Product had no price" is the D9 case (unpriced products are not counted), kept as recommended.
3. **D9 built as recommended** · only products with a price count; label «5 מוצרים עם מחיר».
4. **Contract change logged** · `setup-status` count cap 10 -> 5 is the plan's explicit requirement; recorded under `## Contract extensions (run)` in `docs/mvp/mvp-map.md` (that file is outside the plan's scope block but run-mode allows its extension section). The reader is only the setup card.
5. **Banner decision key** · `needsOpeningDetails_` = owner AND business loaded AND `baseline === undefined`. While the business is still loading, the performance area shows (no flash of the banner for people who already answered).
6. **Banner "title row tappable"** · the icon + title + text are one `<button>` (so the title is a valid phrasing element, a `span`, not an `h2`); the primary button and the tappable row do the same navigation.
7. **Skip does not navigate** · `updateBaseline({})` updates `business_`, so the banner disappears and the performance area appears in place; the dashboard stays where it is.
8. **Card reload on product change (P1, H3-4)** · effect on `KitchenStateService.products_().length`; the first value is only remembered; a later change reloads the status only when the first request was made, the card is not hidden and the user is the owner. The initial product-list load (0 -> N) after the first status request can cause one extra request; accepted.
9. **Progress text built in the component** · the dictionary has no param-substitution in `translatePipe`, so the card replaces `{{done}}` / `{{goal}}` itself (same as `per_diner_in_unit`).
10. **Team tab width** · `.team-tab` is `inline-size: 100%; max-inline-size: 36rem; margin-inline: auto`, so the add-member button (centred) and the list share one centred column.
