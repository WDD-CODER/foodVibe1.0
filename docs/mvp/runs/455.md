## Decisions
- `app-form-field` gets a sixth input `labelStyle: 'default' | 'caps'` (plan lists five) · the product form's labels are small upper-case muted text with a fixed height; "no visual change" needs that look, so the variant is a flag on the shared component instead of a local copy of the field.
- The field is the host element itself (label, projected control, hint, error are direct children of a flex column host) · projected inputs/textareas/`app-custom-select` stretch to full width without `::ng-deep`, and a grid parent (venue, 2 columns at >= 768px) sees `app-form-field` as the grid item; `layout="full"` sets `grid-column: 1 / -1` on the host.
- `label` is a required input (translation key); the product's categories field (label with an icon, chip dropdown) and the venue "active" checkbox have no plain label + input, so they stay as plain wrappers · the equipment "is consumable" checkbox has no wrapper any more (just the `.c-chip-group`).
- Product form: only the plain fields (name, buy price, base unit) moved onto `app-form-field` (`labelStyle="caps"`). The nine other `.form-group` blocks hold custom labels, collapsible headers, purchase rows (`.scaling-box`) or the yield/waste pair with helper text; they were renamed `.product-field` (same rules) because the plan's Out of Scope forbids redesigning the form layout. The spinner-arrow-removal rule for number inputs moved from `.form-group input[type=number]` to `input[type=number]` in the component, because the buy-price input is now projected inside `app-form-field` (same set of inputs as before).
- Supplier, venue and product duplicate-name errors now use the same slot and styling as the required error (`c-field-error` instead of `form-error`; P1 item). Only one of the two shows at a time (duplicate first, then required) - before, both could show together; with a duplicate name the name is non-empty, so the two never applied at once in practice.
- `useUnsavedChanges({ form, snapshot?, extra? })` takes `form` as a function (forms are built in `ngOnInit`). Before the first `markSaved()` it falls back to the form's `dirty` flag (recipe-builder and product-form already did this; venue, menu-intelligence and cook-view used to compare against an empty snapshot, which answered "changed" until the page finished loading - they now answer "not changed" in that short window).
- cook-view: `form` = the steps/prep `FormArray`, `extra` = recipe copy vs original; the edit-mode / original / recipe presence check stays in `hasRealChanges()` · keeps the old order of checks exactly. recipe-builder: `extra` = `unsavedAiDraft_` (kept as a plain boolean, set in six places), `snapshot` = the existing normaliser.
- product-form snapshot normaliser: dropped `?? 0` / `?? 1` after `Number(...)` (never nullish, so no change in output) and replaced the 7-line inline option type with a 2-line alias, to keep the frozen file at net 0 lines.
- Equipment list: no change (only a comment contains `form-group`) · the plan's "one form-group" there does not exist.
- `duplicateNameValidator` is now a thin wrapper over `duplicateEntityNameValidator` (same `{ duplicateName: true }`); `item.validators.spec.ts` passes unchanged.
- Scope additions (small, required): `src/app/core/breadcrumbs.md` (there is no `core/utils/breadcrumbs.md`; the utils row lives in `core/breadcrumbs.md`), `docs/brain/component-families.md` (registry: `form-field` and `entity-form` now say "Known copies: none", as run 450 requires), `docs/mvp/runs/455.md`. Added to the plan's scope block.
- File names `unsaved-changes.ts` / `unsaved-changes.spec.ts` follow the plan's scope list even though neighbours are named `*.util.ts`.
