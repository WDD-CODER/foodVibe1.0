## Decisions
- Staff `POST /products` drops every supplier source that lost its price instead of saving `{ supplierId }` alone · the product schema (`sources[].price: z.number()`, outside this plan's scope and used by the cost engine) rejects a source without a price, so the stored product has `sources: []` and no `price`. Staff therefore cannot link a supplier to a product (adding a source means adding a price, which is `editMoney`); the owner does it.
- `stripMoneyFields` itself still returns `{ supplierId: 's1' }` as the plan's unit case says; the drop happens in the POST route · keeps the helper generic for later plans.
- The route handlers call small helpers (`authorizeEdit`, `authorizeDelete`, `trashOwnerFilter`) that call `assertCan`, so the plan's `grep assertCan` shows 6 lines, not one per handler · one place per rule, no copy-pasted checks in five handlers.
- `PUT` on a type without a v2 schema loads the stored doc just for the permission check · the merge block only runs for v2 types.
- Event actions (`changeStage`, `addNote`, `markArrival`) for staff are denied with `NOT_AN_EVENT` when `ctx.type` is given and is not `menuEvents` · deny by default; no `type` given means the caller vouches it is an event.
- A trash action by a user with no known `businessRole` is refused with 403 `NO_ROLE` · deny by default.
- Unreachable on today's data: every user is an owner until plan 428, so no existing request changes behaviour.
