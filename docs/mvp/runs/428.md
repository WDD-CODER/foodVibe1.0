## Decisions
- Team list/add/remove client code lives in a new `TeamService` (`pages/settings/services/team.service.ts`), not on `BusinessService` · adding it to the initial-bundle service pushed the initial bundle 5 kB over the 560 kB budget (plan 419); the lazy settings chunk now carries it. Recorded as a contract extension in `mvp-map.md`.
- Header settings link uses the already registered `sliders-vertical` icon and the Team tab's add button uses `plus`; `Settings` and `UserPlus` were NOT added to `app.config.ts` · the two icons cost about 0.7 kB of the initial bundle, which was already at the budget edge.
- The header builds its desktop pills and drawer entries from one `@for` over a `navLinks_` computed (the settings link is added for owners) instead of three more `@if` blocks · the unrolled version was 2 kB over budget; the profile-menu entry (mobile) is its own `@if`. The bottom tab bar is unchanged.
- Header reads `UserService.isOwner_` directly, not `PermissionService` · keeps `PermissionService` out of the initial bundle.
- `PermissionService` also exposes `isStaff_`; the price lock and view-only lock apply only to a signed-in staff member · a signed-out visitor or an old session with no role must not get a locked form (and the existing form specs run signed out).
- `team` requests use `environment.apiUrl`, the base `BusinessService` already uses for `GET /business`, not `authApiUrl` · both are the same server; one base for one router.
- `teamLimiter` (10 per 15 min, key = `userId`) wraps `POST /team` only, after the owner check · refused staff requests never use the owner's quota, and listing/removing is not an account-creating action. `DELETE` is idempotent and unlimited.
- Duplicate username is checked on the trimmed name against all businesses, the same rule sign-up applies; the create also maps a Mongo duplicate-key race to 409 `USERNAME_TAKEN`.
- `src/app/core/interceptors/auth.interceptor.spec.ts` added to the plan's scope block · the plan names the interceptor change but not its spec; two cases cover the toast, the info log and the unchanged other-403 path.
- The 403 branch in the interceptor skips the `http.error` log line for `no_permission` and still rethrows the error · so callers' own error handling keeps working.
- Recipe-book delete check reads `recipe.recipeType` (`'dish'` -> type `dishes`, else `recipes`); the plan said to read the actual field name at Step 0 · the model field is `recipeType`, not `recipe_type`.
- Inventory list keeps the disabled delete button for a signed-out visitor and hides it for a staff member on a product he did not create · matches the existing signed-out look.
- Bulk delete stays server-enforced (403 toast), as the plan says; the quick-edit panel/modal price lock stays with plan 444.
- A staff-added team user has no `imgUrl` and a placeholder email `${_id}@staff.foodvibe.invalid`; the email is never returned by `/team` and never shown.
- After a clean `ng build` failure caused by a corrupted incremental cache, `.angular/cache` was moved aside and rebuilt · local build cache only, nothing tracked.
