## Decisions
- `upcoming` leaves out events whose stage is "לא נסגר" (and deleted ones), legacy ones stay with the "ישן" tag · the plan lists "dated today … today + 14"; a lost event is not something the team prepares.
- The period picker is hidden for staff · the period only changes the money cards, which staff never get.
- Funnel shows the six working stages `inquiry` … `post_production` (not "הסתיים", not "לא נסגר") · plan: "one entry per stage `inquiry` … `post_production`".
- "Finished" for revenue and accuracy = `closing.finishedAt` is a number (a reopened event has none) · matches the 446 contract note.
- An event with a snapshot but a planned revenue of 0, or no `plannedProfitPct`, is skipped by the accuracy average (and not counted in `finishedCount`) · no percent can be computed.
- `hasBaseline` is true when at least one of the four baseline numbers is a number (an empty `{ filledAt }` means "skipped") · matches the 431 contract note; revenue baseline needs both closings per month and average revenue.
- When a single baseline number is missing, only that card says "אין נתוני פתיחה" · the other cards still compare.
- Accuracy card: no "% vs before" line until the first finished event (the hint text is shown instead) · avoids "no opening data" being shown when the real gap is "nothing finished yet".
- New dictionary key `stat_points_short` ("נק׳") and `{{pct}}` in `stat_avg_actual_profit` ("רווח בפועל ממוצע {{pct}}") · the plan's table has no text for the "points" unit in the "vs baseline" line, and no slot for the average profit value.
- The "vs baseline" label of the accuracy card reads "−1 נק׳ מול לפני" (same key `stat_vs_before`) · points, not percent, per the plan.
- Revenue is shown through `formatMoney` ("₪48,000.00") · run-mode: money only from `rounding.ts`.
- Rows of "אירועים קרובים" and the funnel bars are buttons; a row opens `/menu-intelligence/<id>` · small usability addition, uses the existing route.
- `server/app.js` mounts `/api/v1/stats` right after `/api/v1/business` · plan scope.
- The staff response is built by the same `shapeStats` without `cards`, and the `usageDays` aggregation is skipped for staff · nothing to compute for a number they never get.
- Timing script treats `DISTINCT_SCAN` over an index as an index scan and prints it as `IXSCAN(<index>)` · MongoDB reports `usageDays` distinct-date grouping that way.
- `breadcrumbs-check` lists `business-stats.model.ts` / the new service as "not mentioned" in `core/models/breadcrumbs.md` and `core/services/breadcrumbs.md` · those files are outside the plan scope; left for `/docs-refresh`.
- Not measured in a browser: the phone layout and the colours (MongoDB down, app empty). The cards cover them.
