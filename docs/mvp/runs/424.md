## Decisions
- Rehearsal source = seeded local dev DB copied into `foodvibe_scratch_0006` · the only Atlas snapshot on disk
  (`atlas-2026-10-20T15-32-31`) is v1-shaped (pre-0001, `RECIPE_LIST` etc.), so migration 0006 cannot run on it; local mongo user cannot `dropDatabase`, so the copy script dropped collections one by one.
- Existing `createdBy` values are kept; only a missing one is filled with the owner's userId · recipes and dishes already carry a client-set `createdBy` (many clones show the master author `dev-guest`); overwriting would erase that history and break idempotency once staff exist (428). Plan 427 treats such docs as owner-only for staff, which is the safe side.
- `tombstoneSchema` also gets optional `createdBy` (plan only listed `businessId`) · migration stamps purged stubs "like any doc" and the strict tombstone schema otherwise rejected them (3 suppliers, 10 products, 9 recipes in the scratch copy).
- `stampNew` leaves `businessId` off when the token has none (pre-migration user) instead of throwing · plan 424 still scopes by `userId`; an old token must keep writing. Plan 425 makes `scopeFilter` strict.
- Login/refresh for a user with no `businessId` yields a token with `businessId: null` and no clone stamp · NO_BUSINESS login block is plan 425's.
- Signup reads the master version before `User.create` and creates the business with it · one lookup, business `lastSyncedMasterVersion` matches the user's.
- `signAccess` / `toPublicUser` helpers in `routes/auth.js` · one place for the token payload; login/signup/guest user objects gain `businessId`, `businessRole`, `isPlatformAdmin`.
- Guest (`dev-guest`) is upserted with `isPlatformAdmin: true` and gets a business via `ensureBusinessForUser` · plan A6.
- Seed-master stamps the taxonomy terms after `buildTerms` (and the v1 `master()` helper) · terms come from the migration-0003 builder, which does not carry the fields.
- POST/replace-all use `stampNew` for every type, so non-v2 types (`VERSION_HISTORY`, `activity_log`) also gain `createdAt` on create · harmless, and replace-all docs previously had none.
- Migration marker doc is `{ _id: '0006-business-tenant', lastRunAt, runs }` with `$inc` · plan wording, re-runs allowed.
- Migration `verify` byBusiness = docs with `userId`, the owner's `businessId` and a `createdBy` · once staff share a business (428) a plain `businessId` count would stop matching; per-userId counting stays valid for the 425 re-run.
