## Decisions
- The plan's `[auto]` ng test command was run with `**/*.spec.ts` globs · the `**` form cannot load non-spec files in Karma.
- Added to the plan's scope block (small, clearly required): `core/engine/testing/event-plan.fixture.ts` (it imported the deleted `portionsFromDerived`; now has its own `derivedPortionsByItem` helper), `core/models/ai-menu-draft.model.ts` (`predictedTakeRate` optional so the page stops setting it), `core/models/menu-event.model.ts` (a comment named `derivePortions`, the grep forbids it), `metadata-manager.page.component.spec.ts` (tab count 11 -> 12) and the two `breadcrumbs.md` files.
- `portionsPerDiner` is the existing form control `serving_portions` (no new control) · it already sits in the dish details; loaded as `portionsPerDiner ?? servingPortions ?? 1`, saved without the old `|| 1`.
- The coefficient box, the portions line, the "שונה ידנית" tag and the reset button live in the dish details rail, after the other dish fields · that is the plan's "existing expandable meta area".
- Typing an empty box in the coefficient field shows no error and changes nothing; leaving the box shows the stored value again · avoids a flashing error while retyping.
- A typed value equal to the default (for example 1.27 when the default is 1.265) still sets an override and shows "שונה ידנית" · the chef typed it, so it is manual.
- Snapshots are frozen in `MenuPortionsService` once the taxonomy is loaded and the key is chosen (also for a new menu in the same session), and a loaded event's snapshots are kept by `remember(event)` · a later change of a term never moves a saved or open menu.
- Menu library AI import now stores snapshots and portions through `EventTypeSnapshotService` + `hydrateDerivedPortions` · same rule as a menu saved from the editor.
- Coefficient card: an add with a name that already exists, or an invalid coefficient, marks the add row invalid with the `coefficient_invalid` text · the plan lists no "name exists" key and dictionary keys were fixed to 13.
- Delete of an event type uses the generic `confirm_delete` text; an event type still used by a menu is refused by the server and shown through `TaxonomyStore.errorMessage` · same pattern as the stations card.
- `MenuEventTypeService.addEventType(name, coefficient = 1)` returns `Promise<boolean>` (false = not saved) instead of void · the card must not show "saved" after a failed write; the menu page ignores the result.
- The AI menu modal (`shared/ai-menu-modal`) still maps the AI's `predictedTakeRate` into `MatchedDish`; nothing reads it any more · it is outside the plan's scope and the greps; harmless leftover.
- Export column widths: the take-rate column is removed, so price moves into column 3 · there is no spare empty column.
- Contract extension logged in `docs/mvp/mvp-map.md` (`MenuPortionsService`, `EventTypeSnapshotService`, `portionInfo`, `coefficient_override`, `addEventType` signature, `derivedPortionsByItem`).
