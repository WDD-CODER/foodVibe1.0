## Decisions
- `export-preview` and `menu-export-sheet` stay off the shell · neither uses the `.c-modal-*` engines (full-screen paper preview; bottom sheet always in the DOM), both already have `role="dialog"` and Escape; moving them would change their look, which the plan forbids. The plan's grep item is met for every engine-based modal.
- `modal-shell/breadcrumbs.md` deleted again · `breadcrumbs-check` flags a breadcrumbs file in a non-seam folder as STRAY; the entry lives in `shared/breadcrumbs.md`.
- Backdrop click is blocked together with Escape while a popup is busy (AI "sending", auth "submitting") via `dismissible` · one input for both; a backdrop click would otherwise drop the request.
- Shell inputs beyond the plan: `cardClass` (page card classes, confirm variants), `labelledBy` / `labelKey` (popups with their own heading or none), `zIndex` (replaces `:host .c-modal-overlay { z-index }` for add-item 1100 / translation-key 1200). Host is `display: contents`.
- Component SCSS that styled the card from outside now uses `:host ::ng-deep` (AI cards, quick-edit card) or a modifier class (confirm message) · the card is rendered inside the shell's view, so encapsulated selectors no longer reach it.
- `ai-menu-modal` / `ai-product-modal` lost their `@HostListener('document:keydown.escape')`; the shell handles Escape and ignores it while sending · Critical Question 2, recommended option.
- Escape on typed, unsaved input closes silently · Critical Question 1, recommended option.
- Escape stack lives in `modal-controller.ts` (`pushModalShell` / `popModalShell` / `isTopModalShell`); a shell that sees `event.defaultPrevented` (open dropdown inside the popup) does nothing.
- Appended `.c-modal-card:focus { outline: none }` to `styles.scss` (the card takes programmatic focus).
- Controller services expose the same signal names (`isOpen`, `isOpen_`) but now read-only; no caller wrote to them.
