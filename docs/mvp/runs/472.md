## Decisions
- Hint under the business-name box is replaced by the error line when an error shows (only the too-long error can occur) · keeps the box to one line of help at a time.
- `BUSINESS_NAME_REQUIRED` branch kept in `_onError` and the dictionary key kept · plan allows it as harmless fallback; the key is reused by the Settings field.
- The Settings name form uses the shared `app-form-field` for label, hint and error · reuse-first (plan 455); the hint slot carries `settings_business_name_help`.
- `app-business-name-form` has its own `margin-block-end` instead of editing `business-settings-tab.component.scss` · that scss is outside the plan's scope.
- Save compares the trimmed text with the stored name; success resets the form to the stored (server-trimmed) name · the box then shows exactly what is stored.
- The `businessNameInputSchema` order is `max(200)` then `trim` then `min(1)` (from the existing `nameField`) · a name of 200 characters plus outer spaces is refused client-side only by length of the raw text; negligible.
