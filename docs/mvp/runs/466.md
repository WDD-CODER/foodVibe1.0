## Decisions
1. **Dictionary key `open_recipe` kept** · `dictionary.json` is an append-only hotspot (no removals without escalating); the key is now unused in code and harmless.
2. **Plan recommendations taken** · deleted row only explains (Q1); link by name in every listed recipe at once (Q2); one search field with the add option built in (Q3); staff who did not create a recipe see the no-permission note (Q4).
3. **`linked` is emitted before the stored write** · the recipe builder form is patched immediately and the badge may be destroyed once its list empties; the stored write and toasts only use injected services, never component state.
4. **Create-window guard released with `setTimeout(0)`** · the click that saves/cancels the window bubbles to the click-outside listener after the promise resolves; releasing a tick later keeps the popover open (S4).
5. **Name match uses the snapshot, else the typed name** · `nameSnapshot ?? nameHebrew` for stored rows (same as `collectMissing`); `nameSnapshot || nameHebrew` for form rows, because the form holds empty strings for blank controls.
6. **Host refresh not given its own new spec** · `menu-dish-row`, `pricing-meter`, `supplier-orders`, `export-preview` read `KitchenStateService` signals, and `saveRecipe` updates the recipe store, so they refresh without host code; their spec files are outside this plan's scope. Card 4 checks it in the browser.
7. **Linked product with no price** · it reappears in the same popover as a «חסר מחיר» row with the price box (existing plan 444 behaviour), as the plan expects.
8. **Add option label** · the field uses `add_new_ingredient` («הוסף מרכיב חדש») when nothing is typed, and `הוסף "<typed>"` once text is typed (`allowTypedAdd`).
9. **Fix round 1, linked row priced in the header** · `onLinked` now sets `total_cost` per patched row via `RecipeCostService.getCostForIngredient` (referenceId, type product, amount_net, unit), so the builder total updates at once; spec added. The ingredients table stays untouched (out of scope).
10. **Fix round 1, stacking** · the popover is taken out of the top layer (`hidePopover()`) while the create window is open, then `showPopover()` plus `place_()` after it closes; spec added. Card 1 SEE (3) changed to match.
11. **Fix round 1, toasts and logs** · `linkTo` no longer logs or toasts on failure (`saveRecipe` already does both). The per-recipe «updated» toasts from `saveRecipe` plus one «המוצר קושר» are accepted: they sit in a shared service outside scope and each is true.
12. **Fix round 1, clipped list** · the link field gets `[maxHeight]="140"` so the list fits the popover; card SEE lines added.
