## Decisions
- Selector `app-pricing-meter` (not `pricing-meter`) · run-mode requires the `app-` prefix.
- Added `src/app/pages/menu-intelligence/_paper-ui.scss` to the plan scope and deleted the orphaned `.financial-footnote` rules there (the look moved into the component) · small, clearly required by "the old footer is replaced".
- The meter reuses the existing keys `profit_target_pct` and `safety_margin_pct` (plan 429) instead of appending duplicates; the other 14 keys of the plan table were appended · `dictionary.json` is append-only and the two keys already exist.
- `MenuEventSaveService.prepareForSave(event, plan, editingId)` also carries over the stored `logistics` of an edited event and sets `performanceTags.foodCostPct` from the pricing (foodCost ÷ revenue) · it needs the id anyway, and it removes the duplicated logistics lines from both page save paths so the frozen page shrinks (net 23 added, 70 deleted).
- Deleted `MenuIntelligenceService.computeEventRevenue` and `computeFoodCostPctFromActualRevenue` (no callers left; the legacy `computeFoodCostPct` stays, its spec uses it) and the library's private `computeEventRevenue` · plan P0 "remove the duplicate revenue functions".
- Page gained `liveEvent_` (the event the form describes) and `menuPlan_` is now `planFor(liveEvent_())`; the meter takes `liveEvent_()` as input · the plan names this as "what `menuPlan_` feeds the engine"; one build per change instead of two.
- The money controls are disabled with `form.disable({ emitEvent: false })` when `can('editMoney')` is false, so `getRawValue()` (snapshot and save) still sees their values · staff see the values locked with the lock icon and `money_locked_hint` as tooltip.
- The target and margin inputs open with the «יעד לאירוע זה» chip, and stay open whenever the event already has `targetsOverride` · so a stored override is never hidden.
- An empty money input leaves its key out of the saved event; an extra-cost note without an amount saves `amount: 0` · plan "empty inputs -> keys left out", and the schema requires `amount` inside `extraCosts`.
- The library food-cost tag shows "—" when `pricing` is absent or revenue is 0; revenue shows "—" at 0 · same as the old revenue behaviour; "חלקי" is appended when `pricing.partial`.
- Sorting by food cost keeps events without `pricing` last in both directions · plan P1 "sort last".
- The «שמור» refusal for an invalid money field uses the existing generic `menu_missing_fields` message plus the inline field error · `menu-form.util.ts` is outside scope.
- Not measured in a browser: layout of the fixed two-row bar and the phone bottom sheet (MongoDB down, app empty). The cards cover it.
