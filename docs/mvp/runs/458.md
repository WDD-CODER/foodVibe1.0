## Decisions
1. **S3 (`@layer`) wraps only the 10 layer-safe files and lists the other 58 as exceptions** · `src/styles.scss` is entirely unlayered, so layering a component that styles a button/input/icon or restyles a `.c-*` engine hands those properties to the global reset/engine - a visual change the plan forbids ("no visual change"). The 10 wrapped files have templates with no such element and no `.c-*`/`::ng-deep` (app shell, dashboard page + header, inventory / recipe-book / menu-library page hosts, ingredient-search, preparation-search, export-toolbar-overlay, form-field). Making the rest layer-safe needs `styles.scss` itself put into layers (its reset in a low layer), which rewrites the append-only hotspot - a Human/Planner decision, not this run.
2. **S11: no OnPush on `cook-view.page.ts` / `recipe-builder.page.ts`** · the plan allows it only when "all reads in the template are signals". They are not: cook-view's template reads the `workflowResetTrigger` getter over a plain counter and `workflowFormArray`; recipe-builder reads `isSubmitted` (a plain field set after `await`s) and the `recipeForm_` reactive form. The line budget was there (cook-view net -12 after S5), so this is not a frozen-file block; it is the plan's own "if not, do NOT add it" branch. Both pages stay the two documented exceptions (Critical Question 1, recommended option).
3. **R1 counts engines *defined* outside `styles.scss`, not restyles** · the cssLayer rule is about where an engine is defined; the plan's literal recipe ("move the block; if the class already exists in `styles.scss` delete the duplicate") would delete 60 scoped restyles and change those pages. Moved: `.c-dense-chip-grid` (recipe book list) to `styles.scss`; dropped the two redundant `.c-dense-chip-col.col-labels/.col-allergens` selectors (the same rule still matches `.col-labels`/`.col-allergens`, no other rule in that file competes on those properties); moved the confirm modal's `--danger`/`--warning` message colours to `styles.scss` with a `.c-modal-card` qualifier so they still win over the modal's own `.confirm-modal-message` colour (component styles load after global ones at equal specificity).
4. **S4 and S5 in one commit** · `custom-select` / `custom-multi-select` carry both a `@ViewChild` and a `@HostListener`; splitting their hunks across two commits without interactive git was not possible. Every other sub-task is its own commit.
5. **`@HostListener` -> `host: {}` metadata, also for `document:` / `window:` targets** (not `fromEvent`) · Angular's host metadata supports the same global targets and registers the same listener the decorator did, so timing and order stay identical; `fromEvent` + `takeUntilDestroyed` would add code in two frozen files.
6. **`clickOutside`'s output keeps its class property name and gets `alias: 'appClickOutside'`** · the template writes `(appClickOutside)="..."`, which both matches the new `[appClickOutside]` selector and binds the output; no caller code changes beyond the rename.
7. **`SelectOnFocus`, `textareaAutoGrow`, `focusByRow` switched to `inject()`** while their files were open · hard rule "inject() for DI - never constructor injection"; no behaviour change.
8. **S8 naming recipe** · `show*`/`hide*` -> `shouldShow*`/`shouldHide*`, `*Error` -> `has*Error`, everything else -> `is*`; `expandAll_` -> `isAllExpanded_`, `allergenExpandAll_` -> `isAllergenAllExpanded_`. 90 renames in one commit, not one per file · the rename is mechanical, `strictTemplates` turns every missed template read into a build error and the full test run covers the specs; 49 build+test cycles would add nothing.
9. **S10 keys go into the `general` section** (42 new keys, Hebrew copied verbatim; existing keys reused where the text was identical: `duplicate_dish_name`, `duplicate_recipe_name`, `name`, `menu_event_type`, `menu_guests`, `menu_serving_style`, `date_filter`, `base_unit`, `ai_product_categories_label`, `allergens`, `metadata_add_category`, `add_new_allergen`). `translate(key) ?? '<hebrew>'` fallbacks in `equipment-list` and `recipe-logistics-picker` were dead (`translate()` returns the key, never null) and are removed. `ScalingService`, `VersionHistoryService`, `RecipeRowActionsService`, `VenueListComponent`, `TrashPage` now inject `TranslationService`.
10. **Scope** · the plan says "add each file via `approved:`"; in this unattended run the run-mode rule applies (small, clearly required -> add to the scope block, log). 115 paths were appended to the scope block under a `# added by the builder` line: template call-sites of the renamed selectors/directives, template/spec reads of renamed signals, the 10 layered stylesheets, the 10 Hebrew files, `docs/mvp/runs/458.md`, and 4 specs (`app.component.spec.ts`, `column-carousel.spec.ts`, `scaling.service.spec.ts`, `inventory-product-list.component.spec.ts`). `.worktree-plan` was written so the slot's scope guard applies this plan's scope (needed for the kit-owned `docs/agent/conventions.md`, which is in scope).
