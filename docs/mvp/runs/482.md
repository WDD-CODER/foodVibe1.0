## Decisions
- Spin rule unlayered at the end of `styles.scss` (the file has no `@layer`; unlayered beats every component layer, per the run-mode CSS trap). Local copies removed with their `-moz-appearance: textfield` lines; plain `appearance: none` lines kept (no effect on look).
- Select-all fix: on the first `mouseup` after a fresh focus the directive now calls `select()` again (besides `preventDefault`), because the caret is placed after `focus` on a desktop click. Touch keeps the focus-time selection; a second click into a focused box still places the caret. Selector widened to `input[type=number]`; standalone components still need the import, so the import was added to the 19 components / pages that had number boxes without it (no template edits).
- Coefficients: typed values are drafts in a signal map (`drafts_`, keyed `kind:key`); the `[value]` binding stays on the stored value so Angular never rewrites the box while typing. «שמור» (`c-btn-primary`, disabled until a changed and valid value exists, disabled while saving, `aria-busy`) saves changed rows one `updateByKey` each in sequence, stops at the first refusal (store message, draft kept), then shows `metadata_updated_success` once. «ביטול» (`c-btn-ghost`, the ai-model-manager pattern) drops drafts and writes the stored values back. Hint `coefficients_unsaved_hint` («יש שינויים שלא נשמרו», appended to dictionary.json). Enter in a coefficient box = «שמור». Invalid typed text shows the existing `coefficient_invalid` error live under its row.
- Leave warning, one question for every way out: `CoefficientManagerComponent.confirmLeave()` opens the existing ternary (`unsaved_changes_confirm`, `leave_without_saving`, `save_and_leave`) and shares one open promise, so a click that both leaves the card and navigates shows one popup. (a) click outside the card -> `ClickOutSideDirective` on the card, ignoring clicks inside `app-modal-shell` / `.c-modal-overlay`; (b)+(c) `canDeactivate: [pendingChangesGuard]` plus `runGuardsAndResolvers: 'paramsOrQueryParamsChange'` on the `dashboard` route, so the guard also runs for a `?tab=` switch (from `setTab`, the header «לוח בקרה» link or the tab chips) — this covers (b) without a separate `setTab` check; `DashboardPage` and `MetadataManagerComponent` forward `hasRealChanges` / `confirmLeave` to the card; (d) `warnBeforeUnload` in the card. `runGuardsAndResolvers` is one extra key on the same approved route entry (the route has no resolvers or canActivate, so nothing else re-runs).
- `PendingChangesComponent` got an optional `confirmLeave()`; the guard uses it when present (after the submitted / disabled checks). Every other page keeps the old flow (spec unchanged and passing).
- The modal's stay button is the existing «ביטול» (the plan's «הישאר» wording); the shared modal was not changed.
- Escalation (plan Escalation Protocol): added to the scope block and written — `src/app/core/guards/pending-changes.guard.spec.ts` (one new case for `confirmLeave`), `src/app/pages/cook-view/cook-view.page.ts` and `src/app/pages/menu-intelligence/menu-intelligence.page.ts` (import of `SelectOnFocusDirective` only; their file names end in `.page.ts`, not `.component.ts`).
- Mobile: the same explicit save applies on phones (as the plan's V1 says); select-all on touch unchanged.
