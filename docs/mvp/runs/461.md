## Decisions
- A1 reproduce in browser - read from code plus a spec instead: the validator did fire for an identical name (only once the box was touched), but the box was not red and the top message did not name a field. Now the name box turns red and shows the message as soon as the text is edited (dirty or touched).
- Validator - `duplicateNameValidator` has its own body on `normalizeProductName` (the one rule); `duplicateEntityNameValidator` (other forms) is unchanged.
- Duplicate message is computed in the template (`@let nameError`) from the control's `duplicateName` error, so `validateForm_` did not grow (frozen file).
- Quantity in the new-unit window - starts empty (null) in product mode only; plain mode keeps its start of `1`, because the plan's scope is the product form.
- Question text - new key `unit_amount_in_base_for_product`; `{{base}}` is the translated base unit chosen in the window, or the word for "base unit" while none is chosen. Old key left in the dictionary.
- Enter in the name box of the unit window still resolves the name key (may open the name-key window); only Tab changed. Per the plan.
- Row layout - children are placed with grid areas by class (`row-unit`, `row-qty`, `row-uom`, `price-override-wrapper`, `row-del`). Desktop column 2 is `minmax(7rem, 9rem)`; the quantity input fills it. At <= 900 px the unit, quantity and compare-to boxes use a 1.5rem symbol column (empty for the unit) plus a filling box. An empty row puts the trash button in the first line.
- The row's amount boxes appear when the unit control has a value; `markForCheck` after the new-unit window answers makes the OnPush view re-render (async result, no DOM event).
- Frozen file trim - removed a duplicate read of the base unit (`currentBaseUnit` = `baseUnitKey`) to pay for the new lines.
- Server not changed; duplicates through other paths are still accepted by the server (Critical Question 3, later plan).
