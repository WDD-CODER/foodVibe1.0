## Decisions
- `optionRateInBase` already takes `Pick<UnitRegistryService, 'getConversion'>` (plan 423 shipped it widened) and its spec already uses a plain object · E4's widening needed no change.
- `MissingItem.productId` is set on `unpriced` and `deleted` entries (the plan's literal fixture omits it, the contract has it as optional) · plan 444's popover needs the id; the spec asserts the rest with `objectContaining`.
- A menu item whose recipe was deleted: `missing` entry `kind: 'deleted'` with `name` = the recipe id (no snapshot exists on a menu item), cost 0, partial · the plan only says "skip with a deleted missing item".
- A dish/prep item with 0 portions is not expanded (no zero-quantity raw lines), but still gets a `DishCost` of 0 · keeps lists clean; its `no_yield` check still runs first.
- A top-level menu item with yield 0 gets `no_yield`, cost 0, partial · same rule as a linked prep.
- Exact values in specs use `toBeCloseTo(x, 9)` · the engine never rounds, so 15 / 0.8 style float noise is possible; `eventFoodCost` is asserted exactly equal to the sum of `dishCosts`.
- `eventFoodCost` is computed as the sum of dish costs, and the specs also assert it equals the sum of raw line costs · the plan requires both to be the same number.
- `prepLine.station` is the serving dish's `defaultStation` trimmed, for nested preps too · per the plan's contract extension.
- `formatQty` returns the normalized key (`gram`, `kg`, `liter`, `ml`) for mass/volume and the original label for any other unit · so each screen can translate the label itself.
- Unit-resolution order in `toBase`: same unit as base, then a purchase option with that symbol, then same-family conversion (mass or volume only), else `null` · mass to volume is never guessed.
- Added shared test helpers (`makeInput`, `makeEvent`, `makeProduct`, `makeRecipe`, `productIng`, `recipeIng`, `FIXTURE_UNITS`) to the fixture file, plus `units.spec.ts` · later plans' specs reuse them; logged in the map's contract extensions.
