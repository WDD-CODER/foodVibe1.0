## Decisions
- The `ClipboardPaste` icon was NOT added to `app.config.ts`; the HeroFab action uses the already registered `clipboard-list` icon · registering it cost ~400 bytes of the initial bundle, which is at its 560 kB budget (plans 428 and 431 did the same). The dictionary got the plan's 19 keys.
- The initial bundle is 70 bytes over the 560 kB warning threshold because of the one required lazy route · nothing else in scope could be trimmed without touching existing code; it is a warning only. A later plan that touches the bundle should win the bytes back.
- `GeminiService.parsePriceList` does not call `incrementGeminiUsage()` itself; `ProductImportComponent.parse` does right after a successful reply · same effect as the `parseText` pattern, and it kept the initial bundle 110 bytes smaller (the service is in the initial chunk, the component is lazy).
- A failed apply shows the existing key `save_failed` («השמירה נכשלה») instead of a new key · reuse first; the error is also sent to `logging.error`.
- Added reason `duplicate` to `skippedRows` (the same name twice in one apply request: the second is skipped) and the `ApplyResult` type · the preview already merges duplicates, this only protects the server from a hand-made request.
- Rows with an unknown `baseUnit` or an empty/over-200-chars name are skipped with reason `invalid` (not a 400 for the whole request) · the plan says a failing row is skipped with `invalid`.
- The apply response never contains prices; the log line `product_import.applied` has counts only, and the parse route logs only the length of an unparsable AI reply (not its text) · plan rule "no prices or names in logs".
- `IMPORT_LIMIT_MAX` (env, default 10) sets the import limiter budget so the route tests can run more than 10 requests · production keeps the plan's 10 per 15 min per user. Rate limit has its own test.
- An empty AI reply gives `200 { rows: [], truncated: false }` (screen shows «לא זוהו מוצרים בטקסט»); invalid JSON gives 502 · plan.
- Category texts that are not known keys are resolved one at a time with `resolveDraftMetadata({ categories: [text] })` then registered together before the apply · `resolveDraftMetadata` returns an unordered de-duplicated list, so one call per text is the only way to know which text became which key. A cancelled translation modal creates the product without a category.
- For an existing product the preview shows name, unit as read-only text and «–» for purchase unit and category (the update never changes them) · plan. If the user edits a new row's name to an existing product's name, the row turns into «קיים – עדכן מחיר» by itself.
- «קיים – עדכן מחיר» / «ללא שינוי» compares with the price under the chosen supplier (or the global price when none is chosen) · plan design (`key = supplierId ?? ''`). A row with no price on an existing product shows «ללא שינוי».
- The apply route's own scope: it reads suppliers (`scopeFilter` + `LIVE`), products and unit terms (`readScope`) of the caller's business only; products are written with `userId`, `businessId`, `createdBy`, `_masterId = _id` like the generic POST.
- Contract extension appended to `docs/mvp/mvp-map.md` (parse route, apply router, helper and client exports, route, dictionary prefix).

## Human checks
Servers: start the stack in slot wt-1 (client http://localhost:4201, API 3001); local MongoDB must be running (it was down when this was built). Sign in as an owner whose business has a supplier «ירקן» (create it in «ספקים» first if missing). The AI quota is used once per «נתח».

▸ Inventory list - http://localhost:4201/inventory/list   (check ①)
① Only the owner has «ייבוא מוצרים» in the «+» menu
   WHY     Prices are money, so the import is the owner's only.
   WHERE   Inventory list, the round «+» button.
   DO      Open the «+» menu as the owner. Then sign in as a staff member (create one in «הגדרות» → «צוות») in a private window and open the same menu.
   SEE ✓   Owner: three entries, the last is «ייבוא מוצרים». Staff: only «הוספת מוצר» and the AI create entry, no «ייבוא מוצרים».
   FAIL ✗  The staff menu shows «ייבוא מוצרים», or the owner does not.

▸ Import page - http://localhost:4201/inventory/import   (checks ②–⑥)
② Pasting a price list gives a preview of new products
   WHY     This is the main new feature: three price lines become three priced products in one go.
   WHERE   «ייבוא מוצרים» from the «+» menu on the inventory list.
   DO      Paste these three lines: `עגבנייה 5.9 לק"ג` / `מלפפון 4.5 לק"ג` / `שמנת 32% 1 ליטר 12`. Pick the supplier «ירקן». Press «נתח».
   SEE ✓   Three rows: «עגבנייה · ק"ג · 5.9», «מלפפון · ק"ג · 4.5», «שמנת 32% · ליטר · 12», each marked «חדש». Press «שמור הכל»: the message «3 נוצרו, 0 עודכנו, 0 דולגו» appears. Open the inventory list: the three products are there with the price under ירקן.
   FAIL ✗  A wrong name, unit or price in the preview (for example 32 read as a price), a row marked something other than «חדש», a different summary, or a missing product.

③ A second list updates the price of an existing product
   WHY     A new price list from the same supplier must not create duplicates.
   WHERE   The same import page, after check ②.
   DO      Paste `עגבנייה 6.2 לק"ג`, keep the supplier «ירקן», press «נתח».
   SEE ✓   One row «עגבנייה» marked «קיים – עדכן מחיר» (name and unit not editable). Press «שמור הכל»: «0 נוצרו, 1 עודכנו, 0 דולגו». In the inventory list עגבנייה now shows 6.2 and there is still only one עגבנייה.
   FAIL ✗  A second «עגבנייה» product, a different summary, or the price stays 5.9.

④ Deleting a row and changing a unit before saving
   WHY     Every row must be checkable and fixable before anything is saved.
   WHERE   The same import page.
   DO      Paste `גזר 3 לק"ג` and `פטרוזיליה 2 ליחידה`, press «נתח». Press the trash icon on the «גזר» row. On the «פטרוזיליה» row change the unit to «גרם». Press «שמור הכל».
   SEE ✓   The summary says «1 נוצרו, 0 עודכנו, 1 דולגו». «פטרוזיליה» exists in the inventory list with the unit גרם; «גזר» does not exist.
   FAIL ✗  «גזר» was saved, the count of skipped is 0, or the unit is not the one you chose.

⑤ Staff cannot open the import page by hand
   WHY     The page must be locked even when the menu entry is hidden.
   WHERE   The import page, signed in as the staff member from check ①.
   DO      Type http://localhost:4201/inventory/import in the address bar.
   SEE ✓   The message «אין לך הרשאה לפעולה הזו» and no paste box.
   FAIL ✗  The paste box appears.

⑥ The page works on a phone
   WHY     Most owners will paste from WhatsApp on a phone.
   WHERE   The import page at a width of 620 px or less (phone, or narrow the browser window), signed in as the owner.
   DO      Paste `עגבנייה 5.9 לק"ג` and `שמנת 32% 1 ליטר 12`, press «נתח». Scroll the preview sideways. Tap a price box and a unit.
   SEE ✓   The paste box, supplier picker and the preview fit the screen; only the preview table scrolls sideways inside its own box (the page itself does not); the name column stays at the edge while scrolling; the phone number keyboard opens for the price.
