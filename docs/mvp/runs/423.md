## Decisions
- Test include globs use `**/*.spec.ts` · the plan's `components/**` also matches html/scss and breaks the Karma build.
- Step 0: 418/377 already replaced the constructor `effect` (INVF-C06 part 1) with `awaitUnitCreated()`; kept it and built `pickNewUnit_` on top for the restore-on-cancel part · every symbol else `ok`.
- Pre-fill only for `kg, gram, liter, ml, tablespoon, teaspoon, cup` (the plan's test list), not every `SYSTEM_UNITS` key · `unit`/`dish`/`portion`/`pinch` are rate 1 g, which is meaningless as a weight for any product.
- Product-mode window starts with amount 0 (save disabled until typed) and basis = the product's base unit · a default of 1 would read as "1 jar = 1 kg".
- A new purchase-row unit keeps `getSuggestedPurchasePrice(price, amount)` as before (it ignores the rate) · price behavior is not part of this plan.
- Base-unit and «:» unit `NEW_UNIT` use the plain window (no `forProduct`) · they define a unit, not a product weight.
- `NEW_UNIT` in a purchase row no longer wipes the row's amount/uom/price · so a cancel can restore the previous unit with its numbers.
- Inventory list `onUnitChange` stamps `uom = old base` on rows that have none when the base unit changes · keeps those rows correct without rescaling.
- Dictionary keys use `{{name}}` / `{{unit}}` placeholders filled in `unit-creator.component.ts` · `translatePipe` has no interpolation.
- Contract extension logged in `docs/mvp/mvp-map.md` (`## Contract extensions (run)`).
