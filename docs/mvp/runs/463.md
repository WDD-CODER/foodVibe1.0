## Decisions
- The "failed" toast shows only when the AI call itself failed (HTTP error, quota), not when the AI answered that a name does not fit · human card 2 requires that an unknown name stays red with no message; the 429 / `daily_limit_reached` case shows the existing `ai_daily_limit_reached_all` instead (plan UI notes).
- `matchNames(items, options?)` takes an optional `{ onAiFailure }` callback and still returns the `Map<key, { product, via }>` the plan names · the table needs to know that the call failed to decide on the toast; plan 464 can ignore the option.
- The toast is a warning (`UserMsgService.onSetWarningMsg`), not an error · "one calm message, no blocking".
- The server drops `null` answers from the response (only real links come back) · the client treats a missing position as "no match"; the response schema still allows `product: null` for the model's raw answer.
- A row patched by the AI step keeps its pasted unit and amount; only reference, type, name and snapshot change · plan S7.
- The client imports the request/response types from `@schemas/ai-product-match.schema` as `import type` only (no zod in the browser bundle); the two max constants are mirrored in the matcher service with a comment · keeps the bundle small.
- `src/app/core/utils/breadcrumbs.md` does not exist; the utils row lives in `src/app/core/breadcrumbs.md`, so `product-name-match.util` was added there (file added to the plan scope) · the breadcrumbs check passes.
- The server test puts the daily-quota case last · the exhausted-model state is saved to Mongo and outlives `resetForTests()`.

## Human checks
HOW TO VALIDATE - 2 checks on 2 pages. Log in as owner (local app of this slot, port 4201). The parsley step calls the real Gemini model; if `GEMINI_API_KEY` is not set on the server, or the daily quota is gone, card 1 can only reach the "stays red + calm message" state: report `unsure`.

### 1. Pasted tomato, parsley and salt link to the products you already have
- PAGE `/recipe-builder` (open any existing recipe from the recipe list, or press the new-recipe button; the ingredients table must be visible)
- SETUP as owner: open `/inventory/list` and make sure three products exist: «עגבנייה», «פטרוזיליה», «מלח» (create the missing ones with the add-product button; a name is enough). Note how many products the list shows.
- DO 1: in the ingredients table press «הדבק מצרכים».
- DO 2: paste exactly these three lines (one per line): `2 ק"ג עגבניות` / `1 צרור פטרוזיליה` / `200 גרם מלח`.
- DO 3: press «הוסף» and wait about 5 seconds.
- SEE ✓ three new rows. The rows named «עגבנייה» (amount 2, unit kg) and «מלח» (amount 200, unit gram) are linked at once and are NOT red. The parsley row may show red «לא מוכן» for a second or two and then its name changes to «פטרוזיליה» (amount stays 1) and it is no longer red. No row stays red.
- DO 4: open `/inventory/list`.
- SEE ✓ the product count is the same as before and no product named «עגבניות» or «פטרוזיליה» was added (only the ones you had).
- FAIL ✗ the tomato or salt row is red, or the parsley row stays red after 10 seconds without a message, or a new product «עגבניות» appears in the inventory.

### 2. A name that is not in the inventory stays red, without an error
- PAGE `/recipe-builder` (any recipe)
- SETUP none besides card 1's products (no product named «שום יבש» may exist; if one does, paste `זנגביל מיובש בכמות קטנה` instead).
- DO 1: press «הדבק מצרכים», paste exactly `שום יבש בכמות קטנה`, press «הוסף», wait about 5 seconds.
- SEE ✓ one new row with the text `שום יבש בכמות קטנה`, red «לא מוכן» (not linked). No red error bar or warning message appears anywhere on the page.
- FAIL ✗ the row links to some other product, or an error / warning message appears.
