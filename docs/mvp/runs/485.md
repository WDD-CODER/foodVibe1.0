## Decisions
- No unique DB index: soft-deleted products keep their names, and a partial index can't say "not deleted". The check runs in the server on every write path instead.
- Keeping the saved name is always allowed (PUT), so old twins can't block price/unit saves before the cleanup runs.
- Removed copies go to the Trash (deletedBy `dedupe-485`), not hard-deleted; restoring one is refused while the kept product has the name.
- Recipe-line stub ("create product from an unlinked name") links the existing product with that name instead of creating a second one.
- Version restore of an old product name relies on the server 409 (generic restore error message) — not worth a special message.
- Login sync: names compare by the name rule; a master rename never renames a clone into a taken name; a master twin is cloned once.
