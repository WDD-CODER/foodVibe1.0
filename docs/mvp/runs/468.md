## Decisions
- G1 cause (found in the browser at 375 px) - the single grid track was as wide as the widest card content (the add row input + button, default input width), so all cards were 399 px wide (x -12..387) inside a 279 px column; on top, `.metadata-page` padded 1.5rem inside the dashboard's own 1.5rem. Fix: `grid-template-columns: minmax(0, 1fr)`, `min-inline-size: 0` on the add input, `padding-inline: 0` on the page at <= 430 px, user list track `minmax(min(100%, 150px), auto)`.
- Scroll-rail arrows at <= 430 px - `--rail-arrow-offset: 0` so the (hidden) arrow no longer sticks out of the bar and caused 7 px of sideways scroll once the page padding was gone.
- Component inputs - `app-inline-rename-field` takes `value` and `ariaLabelKey` (dictionary key, default `edit`); no new dictionary keys (`save`, `cancel`, `edit` exist).
- Handler names - the stations / preparation / section managers keep `onRenameBlur` (plan G2-2); the generic card's own handler is now `onRenameSaved`; the page's is `onMenuTypeRenameSaved`.
- Save closes the field first, then the existing confirm runs (same order as before): declining the confirm leaves the old name and a closed field.
- Sticky chip bar - `inset-block-start: 3.875rem` (header height), `z-index: 5`, background `var(--bg-glass-strong)` + blur instead of the old 45% white, which was see-through once sticky. Sections get `scroll-margin-block-start: 8rem` at <= 1023 px.
- Reduced motion - both the section scroll and `centerChild` use `behavior: 'auto'`.
- G4 - single column per user card, actions row at the inline end; `.item-actions` has 0.125rem padding so the hover wiggle is not clipped.
- Scope - no file outside the plan's Read-Write Scope was changed (the gutter fix was inside `metadata-manager/`; `dashboard.page.scss` untouched).
- Browser isolation - another process was driving the slot's default gstack browse server, so the replay used its own server via `BROWSE_STATE_FILE`.
