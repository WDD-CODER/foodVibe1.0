## Decisions
- Plan 463's `matchNames` is called with only the rows that exact / variant matching did not settle, with `{ onAiFailure }` to raise `import_match_failed` · one AI call at most, only when something is left over.
- A name edit sets `matchedId` to null inside `updateRow` (any patch that contains `name`) · the AI link belonged to the old text, so re-matching is by name only.
- An AI answer is applied to a row only if its name is unchanged since the call started · a user editing during the call must not get a stale link.
- The match inside `view_` is computed from `matchExact` (ambiguous counts as none) and re-evaluated on every edit · instant, no extra state.
- Matched rows keep unit, purchase and category cells read-only, but the name box and price box stay editable · plan S1.
- Unknown pack word = purchase unit text that is neither in `BASE_UNITS` nor in `UnitRegistryService.allUnitKeys_()`, on rows that are not matched (matched rows ignore the pack on save) · plan S5 / question 2 (recommended: chip only).
- Textarea shrink after save: no manual `input` event - `appTextareaAutoGrow` already resizes in `ngAfterViewChecked` when the value changes (text cleared on save) · less code; minimum height stays in the scss.
- `warnBeforeUnload` wired as plan 460 documents, in a constructor in the component · covers reload and tab close on top of the route guard.
- The guard shows the binary "leave without saving" modal (no `saveAndWait`) · saving a preview silently on leave is not wanted.
- Question 4 (greyed unchanged rows): unchanged · plan's recommended answer.
- Prompt: price words «עולה» / «עלות» / «במחיר» / «מחיר» (and misspellings like «עוהל») only mark the price; "N kilo next to a unit" is a quantity; any other word with a number is a pack word · plan S8.
