## Decisions
- Popover contents wrapper - the partial-cost popover got an inner `.partial-body` (scrolls) so the popover itself can be `overflow: visible` and carry an invisible hover bridge over the 8 px gap to the chip (the old popover touched the chip, the shared helper keeps an 8 px gap; without the bridge moving the mouse onto the popover closed it). No visual change.
- `placement` input of `app-partial-cost-badge` is now the preferred side passed to the helper (`'above'` for the bottom bar, `'below'` default); the helper may flip it.
- Phone bottom sheet - on a viewport <= 768 px (`matchMedia`, mirrors `$break-mobile`) the component sets no inline position and clears `max-block-size`; the scss keeps the full-width bottom sheet (`position: fixed; inset-block: auto var(--space-4)`), which is now measured against the viewport because the popover is in the top layer.
- Helper shape - `placeInViewport({ anchor, panel, viewport, prefer })` returns `{ top, left, below, maxHeight, anchorCenterX }`; `maxHeight` is `null` when the panel fits. The nutrition badge keeps `GAP`/`MARGIN` 8 px and min height 80 px (constants moved into the helper); its arrow variable and scroll hints are unchanged.
- Height cap of the partial-cost popover - measured without the inner scroll difference so the existing CSS cap (`min(24rem, 70vh)`) is never lifted by the inline cap; the helper only lowers it when the viewport is tighter.
- Select-on-focus: the "swallow the next mouseup" flag is cleared on `blur` and on a `mousedown` on an already-focused box, so tabbing into a box and later clicking it still places the caret normally. Field named `isFreshFocus_` (rule R7).
- Auto-grow: besides input/change it resizes on `focus`, window `resize` and `ngAfterViewChecked` when the value or the width changed (so `[value]`, `ngModel` and a box shown after being hidden are covered); `overflow-y: hidden` via host style. Its one existing user (recipe-workflow notes) keeps the same 40 px minimum.
- AI recipe window - `appTextareaAutoGrow` added to both textareas of the window (the edit instruction at line 21 and the prompt/paste box at line 168); `appScrollIndicators` stays, its arrows simply never show.
- Karma and `beforeunload` - the Karma page owns `window.onbeforeunload` and reports "full page reload" for any dispatched `beforeunload`, so `leave-warning.util.spec.ts` captures the registered listener and calls it with a fake event instead of dispatching a real one.
- The popover placement specs force the desktop/phone layout by faking the `max-width` media query, because the Karma frame can be narrower than 768 px.
- `app.routes.ts`, `inventory/import` and `settings` untouched (plans 464 / 469 wire the guard and `warnBeforeUnload`). `pendingChangesGuard` logic is unchanged; only its interface comment now documents how a page opts in.
- Other `c-modal-overlay` templates inside a `backdrop-filter` ancestor (static check of each modal's own scss and its direct parent template's scss; no edits made):
  - `new-inquiry-dialog` in `menu-library-list` - fixed by P12.
  - `unit-edit-dialog` in `metadata-manager.page.component.html` (line 167) - the page scss has `backdrop-filter` only on `.manager-card`; the dialog is rendered after `.admin-grid`, outside the cards: no problem found.
