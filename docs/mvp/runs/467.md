## Decisions
- New `app-date-field` also has a `committed` output (fires on leaving the field with an empty or real date, or when a day is picked from the calendar) · the details block saves on commit; `valueChange` fires on every key and would clear the saved deposit date while the owner is still typing.
- The date field has a second model, `invalid` (true once ten characters are typed and they are not a real date) · the parent needs it to block «שמור»; the plan said the field only emits an ISO date or nothing, which cannot tell "half typed" from "impossible".
- Details block: the deposit date now uses `app-date-field` (P1 item in the plan, S6 text).
- `inputmode="numeric"` text field with `maxlength="10"` and `dir="ltr"`; the calendar button opens a hidden native `type="date"` via `showPicker()` (falls back to `click()` when the browser throws).
- Deposit dialog pre-fills today's date in the local timezone (`todayIso()` in `date-input.util.ts`, not UTC) and, when the event already holds a deposit, that date and amount.
- The dialog saves both fields on «שמור»; the amount must be above 0 (Critical Question 2, recommended). Enter in the amount field saves.
- After the stage move the deposit is saved from the event as the store holds it then (`event_()`), not the stale copy from before the move, so the new stage is not overwritten.
- Two requests (stage move, then deposit): if the second fails the event stays in the new stage and `saveFields` shows the error toast; the amount can be typed in «פרטי לקוח» (plan "Technical Considerations", accepted).
- Flame menu: «תפריט חדש» uses `book-plus`, «פנייה חדשה» uses `phone-incoming` (also on the list header button); the header's «תפריט חדש» button keeps its `plus`.
- Stage bar: the row inside the rail is `flex: 0 0 auto; inline-size: max-content; min-inline-size: 100%` so «לא נסגר» stays at the far end on desktop and the row never shrinks below its pills on a phone.
- Four dictionary keys appended at the end of `dictionary.json` (`date_invalid`, `open_calendar`, `deposit_paid_title`, `deposit_amount_required`); existing keys `deposit_date`, `deposit_amount`, `save`, `cancel` reused.
- No row added to `docs/brain/component-families.md` (outside the plan's scope block); the shared `date-field` is in `src/app/shared/breadcrumbs.md`.
- The desktop backdrop bug in the inquiry dialog (plan 460, A8) is not touched.
