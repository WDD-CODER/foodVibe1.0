## Decisions
- Deleted the unused `getServingTypeLabel()` and compressed the `exceljs` type-import comment and file header of `menu-export.service.ts` · the plan's frozen-file budget (net <= 0) needed the lines.
- `shoppingListTable_` in `menu-export.service.ts` now returns the table plus `plan.missing` (one `planFor` call, same as before) · the plan's wording "set `missing: plan.missing` on the payload" without a second plan computation; `shopping-list-table.util.ts` is outside scope.
- The inventory "לא סגור סופית" filter is OR-ed with the "פרטים חסרים" / "לא תקין" chips (same as those two among themselves) and is the only one of the three kept in the URL (`unpriced`) · plan P2 says URL-kept for it only; the other two stay session-local as today.
- A blank builder row (no reference and no name) is ignored by `findMissing`; a row with a name but no reference is `unlinked` · the empty trailing row of the recipe builder must not make a new recipe partial.
- `findMissing` takes plain rows (`type` or `item_type`, `nameSnapshot` or `nameHebrew`) so the builder form rows and stored `Ingredient`s share one walk; unlinked / deleted merge by name, unpriced by product id, like the engine's `addMissing` · same dedupe rule as the engine.
- Recipe-header passes `{[ownerId]: form name}` to the badge (`recipeNames` input) and uses the route `id`, else `'form'`, as owner id · a recipe that is not saved yet is not in `recipesById_`, so the popover could not name it otherwise; «פתח מתכון» is hidden for an owner that is not saved.
- Badge input `placement` (`below` / `above`) added; the menu footer uses `above` · the footer is fixed to the bottom of the screen, a popover opening downward would be off screen. On phones (<= 768 px) the popover is a fixed bottom sheet with a 1 rem gutter.
- Popover opens on hover only on hover-capable devices, on click / Enter everywhere, stays open once clicked or focused, closes on Escape or an outside click · plan UI notes.
- Save button text is `save` ("שמור"), with `quick_price_save` ("שמור מחיר") as its aria-label · the Done-when and the cards say «שמור».
- Unpriced chip in the inventory row reuses `.c-chip.amber`; the badge reuses `.c-chip.amber`, `.c-input`, `.c-btn-primary`, `.c-btn-ghost--sm` · reuse-first rule, no new `.c-*`.
- The badge replaces the supplier card's `partial_total` text; per card it shows the plan's unpriced items whose product is a line of that card · plan P7. A card whose lines are all priced shows nothing.
- Consumer specs (supplier-orders, menu-dish-row, recipe-header) provide mocks for what the badge injects (`ProductDataService`, `KitchenStateService`) · the badge component is always instantiated, even with nothing missing.
- Added to the plan's scope block: `src/app/core/services/export.service.spec.ts` (the test that the preview payload carries `missing`) and `src/app/shared/breadcrumbs.md` (one line for the new `partial-cost-badge/` folder, required by the breadcrumbs rule) · small, clearly required.
- Not measured: how the popover looks inside the recipe-builder metrics square (teal box) and the footer; no browser check was possible (MongoDB down, app empty). The cards below cover it.
