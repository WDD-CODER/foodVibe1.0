## Decisions
- `parseReceiptPhoto` returns a Promise (not an Observable) and does not count usage; the component counts it once with `incrementGeminiUsage()` after success, as for pasted text · plan S5/S7 ("increments the AI usage once").
- Service errors are `Error('IMAGE_TYPE_UNSUPPORTED' | 'IMAGE_TOO_LARGE')` thrown before any request; the component maps `error.message` (and a server `IMAGE_TOO_LARGE` body) to the dictionary keys · plan S6.
- Server checks length > 1,800,000 before the Zod parse so the answer is `IMAGE_TOO_LARGE`, other bad bodies `INVALID_REQUEST` · plan S3.
- A line with no usable number gets no price and `needsReview` (the plan lists only the five price cases) · the owner must fill it in, nothing is guessed.
- The 5% mismatch is measured against the line total: `|unitPrice x quantity - lineTotal| / lineTotal > 0.05` · plan S2.
- The two buttons sit in `.import-paste__row` before the parse button, the privacy note under the row, the check banner at the top of the preview card (above the table) · plan UI notes.
- Photo failures log `productImport.photo_failed` with the HTTP status only (no file name or content) · plan Must-have 5.
- Critical questions: all recommended answers (2026-10-21 Human answers in the plan).
