Audit — no changes made

Design consistency across the 13 screens

I compared every screen on the things that make a family: page shell, header, container radius, buttons, shadows, type scale. The chrome is already unified. The differences are almost all in the page body — width, padding, and the title block. Below: what is consistent, what is not, and what I would change.

Already consistent — do not touch
Top nav — identical on all 11 app screens: sticky, 3.5rem, frosted, same pill spec, same user chip.
Ambient gradient wash — byte-identical everywhere.
Modals — --radius-xl, glass-strong fill, modal blur + shadow on every screen.
Type — the --fs-* scale and the text-color ladder are used almost everywhere.
1

High impact — these are what break the "one app" feeling

A. Page width — 8 different values
most visible issue

Recipe Book 1560 · Inventory / Equipment / Suppliers 1520 · Dashboard / Venues / Metadata 1200 · Recipe Builder 1000 · Venue Detail 920 · Menu Library 900 · Trash 720 · Menu Intelligence 660. Moving between screens, the content column jumps sideways every time.

Proposal: three widths only. 1520 for data screens with a side filter panel (Inventory, Recipe Book, Equipment, Suppliers). 1200 for everything standard (Dashboard, Venues, Metadata, Menu Library, Recipe Builder, Venue Detail). 720 for deliberately narrow ones (Trash, Menu Intelligence). Recipe Book 1560 → 1520; Menu Library 900 → 1200; Menu Intelligence 660 → 720.
B. Page padding — 6 variants

Most screens use space-6 / space-6 / space-12. Metadata uses space-8 all round, Menu Library space-8 space-8 space-12, Trash space-8 space-6 space-12, Recipe Builder space-6 space-6 8rem, Menu Intelligence 0 space-6 7rem. So the first card sits at a different height on almost every screen.

Proposal: one rule — space-6 top and sides, space-12 bottom. Screens with a sticky action footer (Recipe Builder, Menu Intelligence) keep their larger bottom padding, nothing else changes.
C. Page title — three sizes, and two screens have none

Nine screens: --fs-xl bold + a muted --fs-sm subtitle. Metadata: --fs-2xl extrabold plus a bottom border divider no other screen has. Venue Detail: --fs-2xl. Cook View: raw 34px (fine, it is a hero). Menu Intelligence and Recipe Builder have no page title at all — you land there and lose your place in the hierarchy.

Proposal: list & tool screens = --fs-xl bold + subtitle; entity-detail screens (Venue Detail, Recipe Builder) = --fs-2xl bold. Drop the extrabold and the divider on Metadata. Give Menu Intelligence and Recipe Builder a real title row.
D. Header block — four different layouts
  • Data-screen header — panel toggle + title + count + inline search + filters: Inventory, Recipe Book, Equipment, Suppliers. This is the strongest pattern you have.
  • Overview header — title + subtitle left, actions right: Dashboard, Venues, Trash.
  • Inline — title sits in the same row as search, no subtitle: Menu Library.
  • None — Menu Intelligence, Recipe Builder.
Proposal: keep exactly two — data-screen header and overview header — and move Menu Library onto the data-screen one (it already has search). Same 38px control height, same search field spec, subtitle always present with a live count.
2

Medium — noticeable side by side

E. Corner radius — no rule for which container gets which

Cards are --radius-lg on Dashboard and Recipe Builder but --radius-md on Equipment, Inventory, Suppliers, Metadata — --radius-md is used 13–19 times per file, --radius-lg only 2–3. Trash has raw 4px and 6px radii that exist nowhere else.

Proposal — one ladder, applied everywhere: cards & panels --radius-lg (16) · inner rows, inputs, icon buttons --radius-md (12) · chips & pills --radius-full · modals --radius-xl (20). Trash's 4/6px become --radius-xs/--radius-sm.
F. Primary button — two gradients, three paddings

Some screens use linear-gradient(180deg …), others 135deg; padding is 9px 18px / 8px 16px / 8px 20px; font is --fs-sm on some and --fs-xs on Dashboard. Secondary buttons vary the same way.

Proposal: primary = 180deg teal gradient, --radius-full, 9px 18px, --fs-sm/600, --shadow-glow. Ghost = glass fill, --border-default, same size. 135deg stays only on the avatar chip.
G. Shadows — mostly tokenised, a few escapes

Cards use --shadow-glass, but Equipment and Suppliers also carry a one-off --shadow-card and a box-shadow: none !important override, and Menu Intelligence has a hand-written 0 24px 50px -24px …. Small, but it is why some cards read heavier than others.

Proposal: resting card --shadow-glass, hover --shadow-hover, modal --shadow-modal, primary button --shadow-glow. Delete the one-offs.
3

Low — cleanup, worth doing while we are in there

  • Off-scale font sizes. 10px, 10.5px and 8px appear on Dashboard, Suppliers and Recipe Builder — below the smallest token (--fs-xs, 12px). Raise to 12.
  • The nav pills use a literal 13px in every file. Consistent, but it should be a token so it can never drift.
  • Inventory's nav is missing its own self-link — its active item is not the same element as on the other screens.
  • Empty states exist on Dashboard and Inventory (muted line, 320px) but not on the other list screens. One empty-state component for all of them.
  • Mobile touch targets. Controls are 38px and nav pills ~30px; the design system asks for 44×44 minimum on mobile. Also: the system specifies a bottom tab bar on mobile, and we use a horizontally scrolling pill row instead. That is a decision, not a bug — tell me which one you want.
If you approve, I would do it in this order
  1. Pass 1 — the shell (A, B, C). Width, padding and title block on all 13 screens. Mechanical, low risk, and it is 80% of the "same family" feeling.
  2. Pass 2 — header block (D). Menu Library onto the data-screen header; title rows for Menu Intelligence and Recipe Builder.
  3. Pass 3 — the ladder (E, F, G). Radius, buttons, shadows. Touches many lines but each change is small.
  4. Pass 4 — cleanup + mobile decision.

Pass 1 and 2 can go in one turn. Tell me which passes to run, or which individual items to drop.
