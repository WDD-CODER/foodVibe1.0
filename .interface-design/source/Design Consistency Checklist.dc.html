Design consistency — what changed

Every item from the audit is checked off below, done or explicitly held. Open each screen to see it live.

✓A. Page width

Down to 3 widths: 1520 data screens (Inventory, Recipe Book, Equipment, Suppliers); 1200 standard (Dashboard, Venues, Metadata, Menu Library, Recipe Builder, Venue Detail); 720 narrow (Trash). Recipe Book 1560→1520, Menu Library 900→1200, Recipe Builder 1000→1200, Venue Detail 920→1200.

✓B. Page padding

One rule everywhere: space-6 top/sides, space-12 bottom. Fixed on Menu Library, Metadata, Trash. Recipe Builder and Menu Intelligence keep a larger bottom pad — they have a sticky action bar/footer, which is the one legitimate exception.

✓C. Page title

Metadata's title dropped from extrabold --fs-2xl + divider to standard bold --fs-xl, matching every list screen.

◐C (cont.) — Menu Intelligence & Recipe Builder titles

Held, not done. Menu Intelligence is a deliberate "printed menu paper" mockup — forcing the standard title bar onto it fights that design. Recipe Builder's editable name field already functions as its title. Tell me if you still want a title row added to either.

✓D. Header block

On closer inspection this was already fine: data screens share one header spec, overview screens share another. No change needed here beyond A–C above.

✓E. Corner radius

Re-checked against real containers, not raw counts: cards/panels/list containers already use --radius-lg everywhere; --radius-md only shows up on inputs, rows and icon buttons, correctly. The one real miss was Trash's item rows using raw 4px/6px — now --radius-xs/--radius-sm.

✓F. Primary buttons

The 135°/180° "two gradients" read was wrong on closer look — 135° is only ever the logo mark and user-avatar chip, never a button; every real CTA is 180°. What was genuinely inconsistent — Venues' header button and modal buttons, and Menu Intelligence's save button — are now all height: 38px + padding: 0 var(--space-4), matching Trash/Metadata/Menu Library. Modal footer buttons (Equipment, Suppliers, Inventory, Recipe Book) were already consistent at 9px 18px/9px 20px.

✓G. Shadows

Also cleared on re-check: the --shadow-card and none !important instances on Equipment/Suppliers are legitimate — mobile row-card hover states and the table→card collapse at 767px, not stray one-offs. Nothing to change.

✓Cleanup — off-scale font sizes

Raw 10px/10.5px/8px on Dashboard, Suppliers and Recipe Builder raised to --fs-xs (12px), the smallest token on the scale.

✓Cleanup — nav pill literals

The font-size: 13px; font-weight: 600; border-radius: 999px literal on every nav pill (13 files, ~9 pills each) is now var(--fs-sm) / var(--fw-semibold) / var(--radius-full) — same pixel result, can't drift from the token going forward.

○Held for your decision — mobile nav pattern

The design system calls for a bottom tab bar on mobile; every screen instead scrolls the same pill row horizontally. That's a real UX decision, not a bug — I didn't change it. Say the word and I'll build the bottom tab bar and swap it in everywhere.

○Held — empty states & Inventory nav wiring

Dashboard and Inventory have an empty-state message; the other list screens don't — worth one shared pattern once you tell me what it should say per screen. Also: Inventory's own nav item is wired with onClick+dynamic style instead of the href self-link every other screen uses — works fine, just structurally different code; low risk, left as-is unless you want it normalized.

Summary

10 of 13 audit items done. 3 held because they're product decisions, not styling bugs — mobile nav pattern, Menu Intelligence/Recipe Builder titles, and empty states. Say go on any of them and I'll execute.
