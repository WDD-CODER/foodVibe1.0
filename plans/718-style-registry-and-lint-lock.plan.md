## Problem Statement
Plans 704–717 move the pages onto the shared pieces 703 created. Without a close-out the registry still lists the
old copies ("Known copies" in `list-page`, `modal-shell`, `empty-state`, `engine-classes`), the inventory does not show
the new engines' users, and nothing stops the next feature from adding a page-local empty text, a hand-drawn overlay,
a private page width or a literal colour again. This plan records the converged state in
`docs/brain/component-families.md`, regenerates `docs/brain/inventory.md`, adds three reuse-lint rules, and adds one
regression test that runs the style guard over every file the run converged.

Verified on `chore/restaurant-staging` (`d06302a3`, 2026-11-23):
- `scripts/lib/registry-families.mjs` exports `REUSE_RULES` (11 rules; shape `id`, `family`, `files`, `exclude`,
  `pattern`, `skip`, `hint`); `pnpm run lint:reuse` runs `node scripts/reuse-lint.mjs --diff=origin/main`;
  `node scripts/reuse-lint.mjs --check-registry` checks that every rule's family has a heading.
- `docs/brain/component-families.md`: `list-page` "Known copies (4 list pages not on the shell)" names menu-library,
  venue-list, trash, metadata-manager; `modal-shell` "Known copies" names the six popups of plan 713 and the
  equipment side panel (plan 711); `engine-classes` "Known copies: 15 component `.scss` files start a selector with a
  `.c-*` class"; `empty-state` "Known copies: not counted".
- `docs/brain/inventory.md` is generated by `node scripts/inventory.mjs` ("do not edit").
- From 703: `scripts/lib/style-guard.mjs` (`styleFindings`); from 704–717: `scripts/test/style-704…717.test.mjs`, each
  holding its file list as a `FILES` constant.

## Goals & Success Criteria
**Primary:** the registry tells the truth after the run, and a new page-local copy of a converged piece is reported
by the lint the next time someone adds one.

- [auto] `pnpm run test:scripts` passes, including the new `scripts/test/style-718.test.mjs`: it imports `FILES` and `ALLOW` from the fourteen style tests of plans 704–717 in the scripts test folder (each exports them, per those plans; this plan reads them and does not edit them) and asserts `styleFindings(allFiles, { allow: <the union of their allow lists> })` is `[]`; and it asserts that each of the three new reuse-lint rules flags its sample line (`<p class="trash-empty">`, `<div role="dialog">`, `max-inline-size: 36rem;` in a page `.scss`) and passes `<app-empty-state messageKey="x" />`.
- [auto] `node scripts/reuse-lint.mjs --check-registry` exits 0; `pnpm run lint:reuse` exits 0.
- [auto] `pnpm run build` passes; `pnpm run lint` exits 0; `pnpm run test:ci` passes.
- [auto] `node scripts/log-query.mjs --since=plan-start --level=error` → no entries.
- [human] open `/inventory`, `/clients`, `/menu-library`, `/trash`, `/settings`, `/requests`, `/inbox`, `/dashboard` one after the other on a laptop: titles are the same size, lists look like one family, empty and loading states look the same — reply with the page names that still look "different".
